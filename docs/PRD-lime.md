## Product Requirements Document: 라임 선충전 후원과 끊기지 않는 후원 흐름

**Author**: kh.jeon
**Date**: 2026-11-13
**Status**: Draft

## 1. Summary

시청자가 후원하는 동안 방송 영상이 끊기지 않게 한다. 세 가지를 한다.

- **A. 직접결제를 새 탭에서 연다.** 지금의 Toss 직접결제 후원은 그대로 두고 결제 화면만 새 탭으로 옮긴다.
- **B. 결제 후 복귀 경험을 고친다.** 결제가 끝나면 결제 탭을 닫고 방송 탭으로 돌아가며, 방송 탭이 후원 반영을 바로 알린다.
- **C. 라임 선충전 후원을 추가한다.** 현금과 1:1인 서비스 내 단위 "라임"을 Toss 테스트 결제로 미리 충전하고, 방송 화면을 떠나지 않고 잔액에서 차감해 후원한다.

## 3. Background

- 지금 후원은 `DonationPanel`의 "후원하기" → `/broadcasts/:id/donate`(같은 탭) → Toss 결제창(리다이렉트) → `/donations/success` 순서다. 라우트를 옮기는 순간 `LivePlayer`가 언마운트되어 영상이 멈추고, 돌아오면 LIVE에 다시 접속해야 한다.
- 영상이 끊기는 원인은 "결제가 있다"가 아니라 "결제하러 시청 페이지를 떠난다"이다. 그래서 A만으로도 영상 끊김은 대부분 사라진다. 남는 문제는 후원할 때마다 결제창을 거치는 반복 마찰이다. C는 이 마찰을 없앤다.
- 트위치(Bits)·치지직(치즈)도 미리 충전한 단위로 후원한다. 서비스 이름이 Lime이라 단위 이름을 "라임"으로 맞춘다.
- 공모 원문의 도네이션 요건은 "후원 대상과 금액 선택 → 테스트 결제 → 서버가 승인 결과·금액·후원 대상을 확인한 뒤 확정 → 중복 승인 통지에도 한 번만 적립 → 방송별 내역·합계"다. 라임 후원은 PG 승인 시점에 후원 대상이 없으므로 이 요건을 채우지 못한다. **그래서 직접결제 후원을 없애지 않고 유지한다.** 원문 요건은 직접결제 경로가 계속 충족하고, 라임은 두 번째 후원 수단이다.
- 2026-11-13 discover에서 아래 대안을 검토하고 뺐다.

| 대안 | 뺀 이유 |
|---|---|
| 라임만 두고 직접결제 제거 | 원문의 "승인 시 후원 대상 검증"이 약해진다 |
| 잔액 부족 시 "부족분 충전 + 후원"을 결제 한 번에 확정 | 승인 콜백에 충전/충전+후원 분기가 생긴다. 마감 6일 안에서 얻는 것보다 위험이 크다 |
| 결제 전 PiP로 영상 띄우기 | 라우트 이동(언마운트)과 Toss 리다이렉트(문서 교체)에서 PiP가 닫힌다 |
| 방송 화면 위 시트에 Toss 위젯 | 결제창에서 결국 리다이렉트된다. A가 같은 효과를 더 확실하게 낸다 |
| 빌링키 간편결제 | 테스트 모드에서 쓸 수 있는지 확인되지 않았다 |
| 가입 시 라임 지급 | 결제 경로를 거치지 않는다 |

- 마감은 2026-11-19 23:59 KST다.

## 4. Objective

시청자가 후원하는 동안 방송 영상이 멈추지 않고, 반복 후원은 결제창 없이 끝난다.

| 결과 | 측정 | 목표 |
|---|---|---|
| 영상 유지 | 직접결제·라임 후원 각각 진행하는 동안 원래 탭 `<video>`의 `currentTime`이 계속 증가 (Playwright) | 두 경로 모두 멈춤 0회 |
| 라임 후원 마찰 | 잔액이 충분할 때 후원 완료까지 페이지 이동 수와 클릭 수 | 이동 0회, 클릭 2회 이하 (금액 선택, 후원) |
| 잔액 정합성 | 같은 사용자가 잔액보다 많은 라임 후원 요청을 동시에 10건 보냄 | 잔액 음수 0건, 원장 합계 = 잔액 |
| 멱등성 | 같은 충전 승인을 두 번 확인, 같은 라임 후원 요청을 두 번 전송 | 각각 한 번만 반영 |
| 원문 요건 회귀 없음 | 기존 도네이션 테스트·e2e | 모두 통과 |

## 5. Market Segment(s)

- **반복 후원하는 시청자 (로그인)**: 한 방송에서 여러 번 후원한다. 매번 결제창을 거치는 마찰이 가장 크다. 라임의 주 대상이다.
- **처음 후원하는 시청자 (로그인)**: 충전할 이유가 아직 없다. 직접결제를 쓰므로 A·B의 대상이다.
- **심사자**: 테스트 계정으로 짧게 둘러본다. 직접결제(원문 요건)와 라임 후원을 모두 몇 분 안에 확인할 수 있어야 한다.
- **스트리머**: 방송별 후원 내역과 합계를 본다. 후원 수단이 둘이 되어도 합계는 하나로 보인다.

## 6. Value Proposition(s)

**반복 후원하는 시청자**
- **Who**: LIVE 방송을 보며 여러 번 후원하는 로그인 사용자
- **Why**: 방송 흐름을 놓치지 않고 바로 반응하고 싶다
- **What before**: 후원할 때마다 결제 페이지로 넘어가고, 영상이 멈추고, 결제 후 다시 접속한다
- **How**: 한 번 충전한 라임으로 방송 화면 안에서 금액을 고르고 후원 버튼을 누른다
- **What after**: 영상을 보면서 2번 클릭으로 후원이 끝나고, 내역에 바로 나타난다
- **Alternatives**: 직접결제(매번 결제창), 채팅으로만 반응

**처음 후원하는 시청자**
- **Who**: 라임이 없는 로그인 사용자
- **Why**: 한 번 후원하고 싶지만 방송을 놓치고 싶지 않다
- **What before**: 같은 탭에서 결제 페이지로 넘어가 영상이 끊긴다
- **How**: 후원 버튼이 결제를 새 탭에서 연다. 결제를 마치면 그 탭이 닫히고 방송 탭이 "후원이 반영되었습니다"를 띄운다
- **What after**: 결제하는 동안에도 방송 탭의 영상과 소리가 계속 나온다
- **Alternatives**: 방송이 끝난 뒤 후원, 후원 포기

## 7. Solution

### 7.1 A. 직접결제를 새 탭에서

- `DonationPanel`의 "후원하기"를 링크 이동이 아니라 `window.open('/broadcasts/:id/donate', '_blank')`로 연다. 스크립트로 연 창이어야 B에서 `window.close()`가 통한다.
- `DonatePage`·Toss 위젯·`/donations/confirm`과 서버 검증은 바꾸지 않는다.
- 새 탭에서 세션이 없으면 기존 로그인 리다이렉트를 그대로 탄다.

### 7.2 B. 결제 후 복귀

- `DonationSuccessPage`·`DonationFailPage`는 확인이 끝나면 "방송으로 돌아가기"를 보여 준다. 누르면 `window.close()`를 부르고, 창이 닫히지 않으면(주소창으로 직접 연 경우) 방송 페이지로 이동한다.
- 확인에 성공하면 `BroadcastChannel('donations')`(iOS Safari 15.4+, PRD §7.8 범위 안)로 `{ broadcastId }`를 보낸다. 방송 탭의 `DonationPanel`은 이를 받으면 내역을 즉시 다시 가져오고 "후원이 반영되었습니다"를 띄운다. 메시지를 못 받아도 기존 5초 폴링이 반영한다.

### 7.3 C. 라임

**규칙**
- 1라임 = 1원. 화면에는 "1,000라임"처럼 단위를 붙인다. 서비스 이름 "Lime"과 섞이지 않게 단위로만 쓴다.
- 충전: 1회 1,000~100,000라임, 프리셋 1,000·5,000·10,000. 보유 상한은 두지 않는다(상한을 두면 동시 충전 확인에서 상한 초과를 다시 검사해야 하는데, 테스트 결제라 얻는 것이 없다).
- 라임 후원: 금액·메시지 범위와 대상 규칙은 직접결제 후원과 같다(1,000~100,000, 메시지 100자, LIVE 방송만, 자기 방송 거절 = `DonationTargetGuard`).
- 라임 후원 검사 순서: 401 → 400(형식) → 404(방송) → 403(자기 방송) → 409(LIVE 아님) → 409(잔액 부족). 두 409는 사용자용 문구로 구분한다.

**데이터**
- `User.limeBalance Int @default(0)`: 현재 잔액. 차감·적립은 이 컬럼의 조건부 UPDATE로만 한다.
- `LimeCharge`: 충전 주문. `orderId @unique`, `amount`, `status`, `paymentKey @unique`. 지금의 `Donation` 주문과 같은 방식이다.
- `LimeLedger`: 원장. `userId`, `delta`(+충전, −후원), `kind`(CHARGE·DONATION), `refId`, `balanceAfter`. `(kind, refId) @@unique`로 같은 건이 두 번 기록되지 않게 한다.
- `Donation.method`(TOSS·LIME)를 추가한다. 라임 후원은 클라이언트가 만든 멱등 키를 `orderId`로 쓰고, 바로 `APPROVED`로 저장한다.

**흐름**
- 충전: 방송 화면 "충전하기" → 새 탭 `/lime/charge` → `POST /lime/charges`(주문 저장) → Toss → `/lime/charge/success` → `POST /lime/charges/confirm`. 서버는 저장한 주문 금액과 Toss 조회 금액을 대조한다. 한 트랜잭션에서 주문 승인, 잔액 적립, 원장 기록을 한다. 이미 승인된 주문이면 기존 결과를 돌려준다. 성공하면 B와 같이 방송 탭에 알린다.
- 라임 후원: `POST /broadcasts/:id/lime-donations { amount, message, orderId }`. 한 트랜잭션에서 아래를 한다.
  1. `UPDATE "User" SET "limeBalance" = "limeBalance" - n WHERE id = $1 AND "limeBalance" >= n`
  2. 바뀐 행이 0이면 409 "라임이 부족합니다"
  3. `Donation`(method=LIME, APPROVED)과 원장 기록
  4. 같은 `orderId`가 다시 오면 UNIQUE 위반으로 판단하고 트랜잭션을 되돌린다(잔액은 다시 빼지 않는다). 기존 후원이 같은 후원자·방송·금액이면 그 후원을 돌려주고, 아니면 409를 돌려준다(다른 사용자가 같은 키를 쓴 경우)
- 조회: `GET /me/lime`이 잔액을 돌려준다. 방송별 후원 내역·합계는 두 수단을 합쳐 보여 주고, 항목에 수단을 표시한다.

**화면 (방송 페이지 `DonationPanel`)**
- 로그인 사용자에게 잔액, 금액 프리셋 칩, 메시지 입력, "라임으로 후원" 버튼을 패널 안에 둔다. 페이지를 이동하지 않는다.
- 잔액이 부족하면 버튼 자리에 "충전하기"(새 탭)와 "카드로 후원"(A, 새 탭)을 둔다.
- 모바일은 #98의 액션 모음 시트 안에 같은 내용을 둔다.

### 7.4 Assumptions and open questions

| 가정·질문 | 확인 방법 |
|---|---|
| `noopener` 없이 `window.open`으로 연 탭은 Toss 리다이렉트를 거친 뒤에도 `window.close()`로 닫힌다 | Chrome·Safari·Android Chrome에서 직접 확인. 안 되면 "이 탭을 닫아 주세요" 문구로 대신한다 |
| 모바일 브라우저에서 새 탭으로 결제를 열어도 원래 탭의 영상이 계속 재생된다 | Android Chrome·iPhone Safari 실기기. iPhone이 백그라운드 탭을 멈추면 한계로 README에 적는다 |
| Toss 모바일 결제가 카드사 앱으로 넘어갔다 돌아와도 결제 탭의 `successUrl`로 돌아온다 | Android Chrome 실기기에서 테스트 결제 1회 |
| 실서비스라면 라임은 선불전자지급수단(전자금융거래법)으로 등록·환불 의무가 생긴다 | 테스트 결제 공모전이라 범위 밖. README에 한계로 적는다 |

## 8. Release

**1단계 (11-14)**: A·B. 원래 문제(후원 중 영상 끊김)를 먼저 해결한다. 이 단계만으로 제출할 수 있어야 한다.

**2단계 (11-15~16)**: 라임 충전, 잔액, 원장. 동시성·멱등 테스트 포함.

**3단계 (11-17~18)**: 라임 후원 API와 `DonationPanel` UI, 모바일 시트, 인수 시나리오 e2e.

**중단 기준**: 11-18 22:00까지 3단계가 인수 시나리오를 통과하지 못하면 라임은 main에 넣지 않고 1단계 상태로 제출한다.

**인수 시나리오**
1. B가 A의 LIVE 방송에서 "후원하기" → 새 탭에서 5,000원 결제 → 탭이 닫히고 방송 탭에 "후원이 반영되었습니다" → 그동안 영상이 멈추지 않음
2. B가 "충전하기" → 새 탭에서 10,000라임 충전 → 방송 탭 잔액 10,000
3. B가 방송 탭에서 3,000라임 후원 → 페이지 이동 없이 내역에 나타나고 잔액 7,000, 방송 합계 8,000
4. B가 잔액보다 큰 금액을 고르면 "충전하기"와 "카드로 후원"이 보임
5. A는 자기 방송에서 라임 후원 UI를 보지 못하고, API로 보내면 403

**하지 않는 것**
- 라임 환불·출금, 스트리머 정산
- 라임 선물·양도, 유효기간
- 잔액 부족 시 충전과 후원을 결제 한 번에 확정하기
- PiP, 빌링키 간편결제, 가입 보너스 라임
- 선불전자지급수단 등록 등 실서비스 법적 요건
