# 백로그: 송출 화면에서 LIVE 전 방송 삭제 (#252)

- **형식**: User Stories
- **만든 방법**: 구현 뒤에 정리했다. 사용자가 "방송 만들기를 누르면 방송 준비 중으로 목록에 뜨는데, 라이브를 켜기 전에 지우려면 시청 화면으로 넘어가서 삭제해야 해서 불편하다"고 한 말과 `docs/PRD.md` §7.4·§7.5를 근거로 했다.
- **실사용자 데이터 없음**. 근거는 사용자 한 명의 사용 불편과, 방송 준비 중 상한(#212, 20개) 때문에 안 쓰는 방송을 지워야 한다는 점이다.
- **크기 판단**: 문구·UI 한 곳(`docs/agents/pm-skills.md`). 스킬 없이 이슈를 만들고 구현했고, 이 문서는 구현 뒤에 남기는 기록이다. API와 DB는 바뀌지 않는다.

## 정한 것

| 항목 | 값 | 근거 |
|---|---|---|
| 삭제를 두는 곳 | 송출 화면 머리의 "시청 화면 열기" 옆 | 사용자 결정. 방송을 만든 직후와 "방송 준비 중" 카드가 모두 송출 화면으로 열리므로 그 화면에 있어야 한다(`StudioPage.tsx`의 `cardPath`). |
| 보이는 때 | 방송이 `READY`이고 송출 세션이 `idle`일 때만 | 송출 중(연결 중·LIVE)의 종료와 삭제는 기존 흐름(송출 화면 종료 버튼, 시청 화면 `OwnerActions`)이 맡는다. |
| 확인 방식 | 모달(`alertdialog`) | 사용자 결정. 같은 화면의 "송출 중 이탈 확인"(`LeaveConfirm`)과 같은 배경·대화상자 방식이다. |
| 모달 버튼 | 오른쪽 정렬, "취소" 다음에 "삭제하기" | 사용자 결정("모달 버튼은 우측에 붙는 게 일반적"). 실행 버튼이 맨 오른쪽에 오는 관례를 따랐다. 처음 포커스는 "취소"다. |
| API | 바꾸지 않는다 | 기존 `DELETE /broadcasts/:id`(PRD §7.5)를 그대로 쓴다. |

## Stories

#### Story 1: 송출 전에 송출 화면에서 방송을 지운다
**스트리머로서, 방송을 만든 직후 송출 화면에서 바로 그 방송을 지우고 싶다. 그래야 시청 화면까지 가지 않고 잘못 만들거나 쓰지 않는 방송을 정리할 수 있다.**

Acceptance Criteria:
- [ ] `READY`이고 아직 송출하지 않은 방송의 송출 화면에 "방송 삭제" 버튼이 "시청 화면 열기" 옆에 보인다.
- [ ] 버튼을 누르면 확인 모달이 뜨고, 모달에서 "삭제하기"를 누르기 전에는 `DELETE /broadcasts/:id`가 나가지 않는다.
- [ ] "삭제하기"를 누르면 방송이 지워지고 "내 방송"(`/studio`)으로 이동한다. 지운 방송은 목록에 없다.
- [ ] 소유자가 아닌 사람에게는 송출 화면 자체가 "권한이 없습니다"이므로 버튼이 보이지 않는다.

Priority: P1 | Effort: S | Dependencies: none

---

#### Story 2: 송출 중에는 삭제를 보이지 않는다
**스트리머로서, 송출 중인 방송을 실수로 지우지 않기를 원한다. 그래야 방송이 갑자기 끊기지 않는다.**

Acceptance Criteria:
- [ ] 송출 세션이 연결 중·LIVE·종료 중이면 "방송 삭제"가 보이지 않는다.
- [ ] 방송이 `LIVE`이거나 `ENDED`면 보이지 않는다. 종료는 기존 "방송 종료" 흐름을 쓴다.
- [ ] 송출 연결에 실패해 `idle`로 돌아오고 방송이 아직 `READY`면 다시 보인다.

Priority: P1 | Effort: S | Dependencies: Story 1

---

#### Story 3: 확인은 모달로, 실수로 지워지지 않게
**스트리머로서, 삭제 전에 한 번 더 묻는 모달을 보고 싶다. 그래야 되돌릴 수 없는 삭제를 실수로 누르지 않는다.**

Acceptance Criteria:
- [ ] 모달은 `alertdialog`(이름 "삭제 확인")이고 문구는 "이 방송을 삭제할까요? 삭제하면 되돌릴 수 없습니다."다. 시청 화면 `OwnerActions`의 READY 삭제 문구와 같다.
- [ ] 버튼은 오른쪽에 "취소", "삭제하기" 순서로 놓이고, 처음 포커스는 "취소"에 있다.
- [ ] "취소"나 Esc로 닫으면 방송은 그대로이고 삭제 요청이 나가지 않는다.
- [ ] 삭제 요청 중에는 "삭제하기"와 "취소"가 비활성이고 Esc로 닫히지 않는다.

Priority: P1 | Effort: S | Dependencies: Story 1

---

#### Story 4: 삭제가 실패하거나 이미 지워졌을 때
**스트리머로서, 삭제가 안 되거나 다른 곳에서 이미 지운 경우에도 막힌 화면에 남지 않기를 원한다.**

Acceptance Criteria:
- [ ] 서버가 404(이미 삭제됨, 예: 다른 탭)를 돌려주면 `/studio`로 이동한다.
- [ ] 401이면 로그인 화면으로 보내고, 로그인한 뒤 이 송출 화면으로 돌아온다.
- [ ] 403이면 "권한이 없습니다.", 그 밖의 실패는 "삭제하지 못했습니다. 잠시 후 다시 시도해 주세요."를 버튼 아래에 보이고 모달은 닫힌다.

Priority: P2 | Effort: S | Dependencies: Story 1

---

### Technical Notes

- 구현: `apps/web/src/components/DeleteBroadcast.tsx`(+ `.module.css`)를 `PublishPage.tsx`의 `Heading`이 `actions`로 받는다. 버튼 스타일은 `OwnerActions.module.css`를 같이 쓴다.
- 보이는 조건은 폴링으로 읽은 방송 상태(`broadcast.status === 'READY'`)와 `session.state.kind === 'idle'`이다. 다른 탭이나 OBS가 방송을 시작하면 다음 폴링(5초) 안에 버튼이 사라진다. 그 사이에 누르면 API가 처리하고, 이미 LIVE였다면 시청 화면과 같은 방식으로 삭제된다.
- 시청 화면 `OwnerActions`의 삭제는 그대로 둔다. 두 곳의 삭제 로직이 비슷해 중복이지만, `OwnerActions`는 종료와 삭제가 한 확인 상자를 공유해서 합치지 않았다.
- 모달은 포커스를 가두지 않는다. `LeaveConfirm`과 같은 방식이고, Esc와 초기 포커스만 처리한다.

### Open Questions

- 좁은 화면(휴대폰)에서 머리 줄이 어떻게 접히는지는 실기기로 확인하지 못했다. 시나리오 PD5에서 확인한다.
- 같은 방송 상태를 쓰는 삭제가 시청 화면과 송출 화면 두 곳에 있다. 한 곳으로 합칠지는 정하지 않았다.
- 쓰지 않는 방송이 24시간 뒤 공개 목록에서 빠진 뒤에도 "내 방송"에 남는 문제와 READY 개수 정책은 별도 이슈로 다룬다.
