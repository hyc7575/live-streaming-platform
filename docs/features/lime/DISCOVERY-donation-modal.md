# 탐색: 후원 모달과 PC 결제 화면 유지

- 날짜: 2026-11-15
- 단계: 기존 기능 개선(라임·카드 후원은 구현 완료, [PRD.md](./PRD.md))
- 근거: 실사용자 데이터 없음. 근거는 사용자의 직접 사용 피드백, 치지직·Twitch의 공개 동작, 토스페이먼츠 공개 자료다.

## 탐색 질문

시청 화면에서 후원할 때, PC에서는 결제하는 동안에도 방송 화면을 보이게 둘 수 있는가? 그 방법이 마감(2026-11-19) 안에 안전하게 들어가는가?

## 배경

- 지금은 방송 패널 안에 라임 후원 폼이 늘 펼쳐져 있다. "후원하기" 버튼은 카드 결제 탭을 바로 연다.
- "충전하기"·"카드로 후원"은 `window.open(..., '_blank')`로 새 탭을 연다(PRD §7.1·7.3). 방송 탭의 영상은 계속 재생된다. 하지만 브라우저가 새 탭으로 화면을 넘기므로, 사용자는 "방송 화면을 이탈한다"고 느꼈다.
- 사용자가 정한 방향
  - "후원하기"를 누르면 후원 폼을 모달로 띄운다.
  - PC에서는 충전·카드 결제를 모달 안 iframe으로 연다.
  - 모바일은 지금처럼 새 탭을 쓴다.

## 비교한 방안

방향이 정해져 있어 발산은 대안 비교로 줄였다.

| # | 방안 | 방송 화면 | Toss 지원 | 판단 |
|---|---|---|---|---|
| A | PC는 모달 안 iframe, 모바일은 새 탭 | 보인다 | 비권장(아래 가정 1) | 선택. 검증 후 진행 |
| B | 결제 화면을 지정 크기 팝업 창(`window.open` + width·height)으로 연다 | 팝업 뒤로 보인다 | 최상위 창이라 지원 범위 안 | A가 실패할 때의 PC 대안 |
| C | 모두 지금처럼 새 탭에 두고, 후원 폼만 모달로 바꾼다 | 탭이 넘어간다 | 지금과 같음 | 최소 대안 |
| D | 방송 페이지에서 Toss 결제창을 직접 띄운다(Toss 기본 iframe 레이어) | 결제 중에는 보인다 | 지원 | 탈락. 결제 성공 시 `successUrl`이 방송 페이지 전체를 이동시켜 영상이 끊긴다 |
| E | 결제 탭으로 넘어갈 때 PiP로 영상을 띄운다 | PiP로 보인다 | 상관없음 | 탈락. 브라우저마다 PiP 진입 조건이 달라 범위가 크다 |

### 믿음의 도약

가정 1과 2다. 토스페이먼츠 기술 문의 답변은 iframe 안 결제창을 권장하지 않는다고 했다. 이유로는 Chrome의 CORS 차단을 들었다. 굳이 써야 한다면 `windowTarget: 'self'`를 쓰라고 안내했다. 다만 이 답변은 약 1년 전 것이다. 현재 SDK 2.10.0에서는 직접 확인해야 한다.

### 판단 기준

- E1이나 E2가 Chrome과 Safari 모두에서 통과하면 방안 A로 PRD를 쓴다.
- 둘 중 하나라도 실패하면, PC는 방안 B(팝업 창)로 간다. 후원 폼 모달은 그대로 진행한다.
- 11-16 안에 E1을 끝내지 못하면 방안 C로 범위를 줄인다. 이렇게 해서 #17 회귀 일정을 지킨다.

## 실험 결과 (2026-11-16)

| 실험 | 결과 |
|---|---|
| E1 | Chrome 부분 통과. 기본 `windowTarget`으로는 승인 뒤 Toss가 우리 iframe 주소를 바꾸려다 교차 출처 이동 차단에 막혀 실패했다. 결제 수단은 퀵계좌이체였다. Safari는 이때 하지 않았고, 2단계 머지 뒤(11-16) PC Safari에서 LIVE 방송을 보며 모달 안 충전과 카드 후원을 끝까지 마쳐 통과했다. 방송 탭 URL은 그대로였고 영상은 멈추지 않았다([PRD-donation-modal](./PRD-donation-modal.md) 8.1 결과) |
| E2 | 통과. `windowTarget: 'self'`면 iframe 안에서 Toss 결제 페이지로 갔다가 `successUrl`로 돌아와 충전이 끝났다. 방송 탭 URL은 그대로였다(#179 운영, #181 로컬) |
| E3 | 결제 취소 화면이 iframe 안에서 열리고 "돌아가기"로 폼에 돌아온다(#181, 실패 URL을 직접 열어 확인). 카드 거절은 하지 않았다 |
| E4 | 통과. 1366×768에서 "결제하기"까지 스크롤 없이 닿는다(`docs/screenshots/181/`) |
| E5 | #17 회귀에서 한다 |

결정: 방안 A(PC는 모달 안 iframe, `windowTarget: 'self'`)로 갔다. 근거와 남은 확인은 [PRD-donation-modal](./PRD-donation-modal.md) 8.1 "결과"에 있다.
