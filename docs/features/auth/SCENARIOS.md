## AU1. 회원가입 → 로그인 → 새로고침 유지 → 로그아웃

- **요구사항**: §8.3 0, §7.1 "인증"
- **사전 조건**: 비로그인. 처음 쓰는 이메일.
- **역할**: 새 사용자
- **우선순위**: Critical

| 단계 | 행동 | 기대 결과 |
|---|---|---|
| 1 | 헤더 "로그인" → 회원가입 화면에서 이메일·비밀번호·닉네임 입력 → 가입 | "가입했습니다. 로그인해 주세요." |
| 2 | 같은 이메일·비밀번호로 로그인 | 헤더 오른쪽에 프로필 원과 닉네임이 보인다 |
| 3 | 새로고침 | 로그인 상태가 그대로다 |
| 4 | 브라우저를 완전히 닫았다가 다시 연다 | 로그인 상태가 그대로다 |
| 5 | 사용자 메뉴 → "로그아웃" | 헤더에 "로그인"이 보인다 |
| 6 | 방송 만들기(`/studio/new`)로 간다 | 로그인 화면으로 간다 (API는 401) |

**사후 상태**: 새 계정이 남는다. 다음 회귀에는 다른 이메일을 쓴다.

## AU2. 테스트 계정 원클릭 로그인

- **요구사항**: §7.1 "인증"의 테스트 계정, §6 심사자
- **사전 조건**: 비로그인. 서버에 테스트 계정 환경변수가 있다.
- **역할**: 심사자
- **우선순위**: Critical

| 단계 | 행동 | 기대 결과 |
|---|---|---|
| 1 | 홈(`/`)을 연다 | 소개 한 줄 옆(좁으면 아래)에 "스트리머 A"·"사용자 B" 버튼이 있다 |
| 2 | "스트리머 A"를 누른다 | 홈에 머문 채 헤더가 "스트리머 A"로 바뀐다. 테스트 계정 버튼은 사라진다 |
| 3 | 로그아웃 → 로그인 화면에서 "사용자 B" | "사용자 B"로 로그인된다 |
| 4 | 360px 폭(휴대폰)에서 1~2단계 | 버튼이 화면 밖으로 넘치지 않는다 |

## AU3. 비로그인으로 방송 만들기 → 로그인 화면

- **요구사항**: §8.3 1
- **사전 조건**: 비로그인
- **역할**: 시청자
- **우선순위**: Critical

| 단계 | 행동 | 기대 결과 |
|---|---|---|
| 1 | 주소창에 `/studio/new`를 연다 | 로그인 화면으로 간다 |
| 2 | 그 화면에서 "스트리머 A"로 로그인 | 원래 가려던 방송 만들기 화면으로 돌아온다 |
| 3 | 비로그인 상태의 다른 기기에서 `POST /api/broadcasts`를 직접 호출 | 401 |

## AU4. 로그아웃이 서버에서 세션을 지운다

- **요구사항**: §7.10 A3 ("로그아웃이 서버에서 실제로 무효화된다")
- **사전 조건**: 로그인. DevTools에서 세션 쿠키 값을 복사해 둔다.
- **역할**: 사용자 B
- **우선순위**: High

| 단계 | 행동 | 기대 결과 |
|---|---|---|
| 1 | 복사한 쿠키로 `GET /api/auth/me`를 호출 | 200, B의 정보 |
| 2 | 화면에서 로그아웃 | 헤더가 비로그인으로 바뀐다 |
| 3 | 1단계와 같은 쿠키로 다시 호출 | 401 |

## AU5. 서버를 재시작해도 로그인이 유지된다

- **요구사항**: §7.10 A3 (세션 저장소가 PostgreSQL)
- **사전 조건**: 로그인. 서버 접속 권한.
- **역할**: 운영자 + 사용자
- **우선순위**: Medium

| 단계 | 행동 | 기대 결과 |
|---|---|---|
| 1 | 서버에서 API 컨테이너를 재시작 (`docs/OPERATIONS.md` 절차) | API가 다시 뜬다 |
| 2 | 브라우저를 새로고침 | 로그인 상태가 그대로다 |

## AU6. 다른 탭에서 로그아웃한 뒤 원래 탭의 요청

- **요구사항**: #78 (401을 받으면 로그인 상태를 비로그인으로 바꾼다)
- **사전 조건**: 같은 브라우저에서 탭 두 개를 열고 로그인
- **역할**: 사용자 B
- **우선순위**: Medium

| 단계 | 행동 | 기대 결과 |
|---|---|---|
| 1 | 탭 2에서 로그아웃 | 탭 2가 비로그인이 된다 |
| 2 | 탭 1에서 LIVE 방송 채팅을 보낸다 | 로그인 화면으로 간다. 헤더가 비로그인으로 바뀐다 |

## AU7. 잘못된 입력

- **요구사항**: §7.1 "인증"
- **사전 조건**: 비로그인
- **우선순위**: Medium

| 단계 | 행동 | 기대 결과 |
|---|---|---|
| 1 | 틀린 비밀번호로 로그인 | 오류 문구가 보이고 로그인되지 않는다 |
| 2 | 이미 있는 이메일로 가입 | 오류 문구가 보이고 가입되지 않는다 |
| 3 | 빈 칸으로 제출 | 요청을 보내지 않거나 오류 문구가 보인다. 화면이 깨지지 않는다 |

## AU8. 로그인 시도가 너무 많을 때

- **요구사항**: §7.9 (로그인 API 요청 횟수 제한)
- **사전 조건**: 비로그인
- **우선순위**: Low

| 단계 | 행동 | 기대 결과 |
|---|---|---|
| 1 | 틀린 비밀번호로 짧은 시간에 여러 번 로그인 | "로그인 시도가 너무 많습니다. 잠시 후 다시 시도해 주세요." |
| 2 | 잠시 기다린 뒤 맞는 비밀번호로 로그인 | 로그인된다 |

> 이 시나리오 뒤에는 같은 IP의 로그인이 잠시 막힌다. 회귀의 마지막에 한다.

## AU9. 세션 쿠키 속성

- **요구사항**: §7.9 세션 쿠키, PRE-MORTEM T10, #25
- **사전 조건**: 로그인. DevTools.
- **우선순위**: Medium

| 단계 | 행동 | 기대 결과 |
|---|---|---|
| 1 | DevTools → Application → Cookies에서 세션 쿠키를 본다 | `Secure`, `HttpOnly`, `SameSite=Lax` |
| 2 | `http://` 주소로 접속한다 | Caddy가 `https://`로 리다이렉트한다. API에 https가 아닌 요청이 닿으면 세션을 만들지 않고 403이다 (#25) |
