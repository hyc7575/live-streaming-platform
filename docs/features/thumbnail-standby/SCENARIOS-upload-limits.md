# 테스트 시나리오: 이미지 업로드 본문 한도 (#211)

`/pm-execution:test-scenarios`로 [STORIES-upload-limits.md](./STORIES-upload-limits.md)의 수락 기준에서 만들었다.

- 시나리오 수: 7
- 범위: 정상 경로, 경계, 오류, 보안
- 자동 회귀: `apps/api/test/image-upload-limits.e2e.spec.ts` (시나리오 1~5를 세 라우트마다 실행)
- 기기 구분 없음: 웹 화면은 바뀌지 않고, 정상 클라이언트는 `image` 파트 하나만 보낸다.

대상 라우트: `PUT /api/me/avatar`, `PUT /api/me/standby-image`, `PUT /api/broadcasts/:id/thumbnail`

### 시나리오 1: 이미지 파일 하나만 보내면 저장된다
**검증 대상**: 스토리 1 (정상 업로드는 지금처럼 성공)
**사전 조건**: 로그인한 사용자, 썸네일은 LIVE 방송의 소유자
**우선순위**: Critical

| 단계 | 행동 | 기대 결과 |
|---|---|---|
| 1 | `image` 파트 하나(JPEG)만 담아 PUT | 2xx |
| 2 | `/api/auth/me` 또는 방송 상세 조회 | 이미지 URL이 생긴다 |

### 시나리오 2: 텍스트 필드가 하나라도 붙으면 400
**검증 대상**: 스토리 1
**우선순위**: Critical

| 단계 | 행동 | 기대 결과 |
|---|---|---|
| 1 | 이미지 뒤에 `note=x` 필드를 붙여 PUT | 400, `message`는 라우트의 `invalidMessage` |
| 2 | 필드를 이미지 앞에 두고 PUT | 같은 400 |
| 3 | 이미지 URL 조회 | 여전히 `null` |

### 시나리오 3: 1 MiB 텍스트 필드
**검증 대상**: 스토리 1 (감사 재현 조건)
**우선순위**: High

| 단계 | 행동 | 기대 결과 |
|---|---|---|
| 1 | 이미지 + 1 MiB 필드로 PUT | 400, 같은 문구, 이미지 미저장 |

### 시나리오 4: 텍스트 필드 32개
**검증 대상**: 스토리 1 (감사 재현 조건의 개수)
**우선순위**: High

| 단계 | 행동 | 기대 결과 |
|---|---|---|
| 1 | 이미지 + 필드 32개로 PUT | 400, 같은 문구, 이미지 미저장 |

### 시나리오 5: 파일 파트가 둘이거나 이름이 다르다
**검증 대상**: 스토리 2
**우선순위**: High

| 단계 | 행동 | 기대 결과 |
|---|---|---|
| 1 | `image` 파트 두 개로 PUT | 400, 같은 문구 (영어 multer 문구 아님) |
| 2 | `image` + `other` 파일 파트로 PUT | 400, 같은 문구 |

### 시나리오 6: 기존 무효 이미지 동작 유지
**검증 대상**: 스토리 2 (한도 오류의 문구 통일)
**우선순위**: Medium
**자동 회귀**: `standby-image.e2e.spec.ts`, `thumbnails.e2e.spec.ts`, `profile.e2e.spec.ts`

| 단계 | 행동 | 기대 결과 |
|---|---|---|
| 1 | 규칙보다 1바이트 큰 이미지로 PUT | 400, 같은 문구 |
| 2 | `image` 없이 `other` 필드만 보내 PUT | 400, 같은 문구 |
| 3 | 형식이 틀린 바이트로 PUT | 400, 같은 문구, 이전 이미지 유지 |

### 시나리오 7: Caddy가 4 MiB보다 큰 `/api/*` 본문을 막는다
**검증 대상**: 스토리 3
**사전 조건**: 운영 서버에 새 Caddyfile 반영(운영 조치 필요). 저장소에서는 `caddy validate`만 확인했다.
**우선순위**: Low

| 단계 | 행동 | 기대 결과 |
|---|---|---|
| 1 | 2 MiB 대기 이미지 업로드 | 200 |
| 2 | 5 MiB 본문으로 `/api/me/avatar` PUT | 413, API 로그에 요청 본문이 쌓이지 않는다 |

## 수락 기준 대응표

| 수락 기준 | 정상 경로 | 경계 | 오류 | 비고 |
|---|---|---|---|---|
| 텍스트 필드가 하나라도 있으면 400 | 1 | 3, 4 | 2 | 자동 |
| 400 문구는 `invalidMessage`, 이미지 미변경 | | | 2~5 | 자동 |
| 정상 업로드 성공 | 1 | | | 자동 |
| 모든 multipart 한도가 유한 | | 5 | 5, 6 | 자동 + 코드 |
| 파일 파트 둘이면 400 | | | 5 | 자동 |
| Caddy `max_size` | 7 | | 7 | 수동, 운영 반영 뒤 |

## 테스트 데이터

- 64바이트 JPEG(매직 바이트 `FF D8 FF E0`). 세 라우트가 모두 받는 형식이다.
- LIVE 상태 방송 한 개(썸네일 라우트용).
