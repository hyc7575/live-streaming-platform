## Backlog: LIVE가 된 직후 10초는 공개 화면에 "방송 준비 중"으로 보인다

**Format**: User Stories
**출처**: 2026-11-17 iOS Simulator 측정(#246, #248)에서 본 송출 직후 재생 대기. 사용자 결정: 대기 시간의 중위값만큼 공개 화면의 LIVE 표시를 늦춘다.
**이슈**: #249
**Total stories**: 1
**Estimated total effort**: 약 2~3시간 (M)

실사용자 데이터 없음. 근거는 공모 원문 2절 1항·3항(시청, 방송 중·종료 상태 구분), README 확인 순서 1·2번과 아래 측정값이다.

### 무엇이 문제인가

방송은 만들면 바로 "방송 준비 중"(READY)으로 목록에 오르고(#90), 시청자는 그 화면에서 기다릴 수 있다. 송출이 붙어 LIVE가 되면 시청 화면은 5초 조회로 그것을 읽고 대기 화면을 플레이어로 바꾼다. 그런데 그 순간 OME의 LL-HLS 플레이리스트가 아직 없다. OME는 첫 세그먼트가 닫힐 때까지 플레이리스트에 404를 주고(#102), 세그먼트는 송출자의 키프레임에서만 잘린다(비디오 bypass). 그래서 시청자는 "방송을 불러오는 중입니다"를 한동안 본다.

| 측정 (2026-11-17, 운영, iOS 26.5 Simulator·Mac) | 값 |
|---|---|
| LIVE 뒤 플레이리스트가 200이 된 시각 | 15.7초 (1회), 11~16초 사이 (1회) |
| LIVE 뒤 6초에 연 시청 화면이 재생을 시작하기까지 걸린 시간 (#248) | 8.4초, 12.4초, 13.6초 |
| 같은 측정을 LIVE 뒤 시각으로 바꾸면 | 14.4초, 18.4초, 19.6초 |

### 결정

- 지연값은 **10초**(`LIVE_DISPLAY_DELAY_MS = 10_000`)다. 처음에는 시청자가 기다린 시간 8.4·12.4·13.6초의 중위값(12.4초)을 바탕으로 10초를 잡았고, 사용자가 10초로 정했다. 20초는 송출자와 시청자 사이의 어긋남이 길어 고르지 않았다.
- 10초로는 다 가리지 못한다. LIVE 뒤 재생 가능 시각이 14~20초였으므로, 플레이어로 바뀐 뒤에도 몇 초 로딩이 남는 경우가 있다. 로딩 문구는 그대로 둔다.
- 서버와 상태 전이(READY → LIVE → ENDED, PRD §7.4)는 바꾸지 않는다. 웹이 공개 화면에 보이는 상태만 바꾼다. 송출 화면과 소유자 조작은 실제 상태를 쓴다.
- 기준 시각은 `startedAt`(LIVE가 된 시각)이다. 재접속(LIVE → LIVE)은 `startedAt`이 그대로라 다시 늦추지 않는다.

### Stories

#### S1: 송출이 막 붙은 방송은 10초 동안 "방송 준비 중"으로 보인다
**시청자(심사위원)로서, 방송이 LIVE로 보이는 순간 바로 영상이 나오기를 원한다. 그래야 LIVE를 눌렀는데 로딩만 보는 시간이 줄어든다.**

Acceptance Criteria:
- [ ] 웹의 한 곳(예: `src/broadcasts.ts`)에 `LIVE_DISPLAY_DELAY_MS = 10_000`과 표시 상태를 정하는 함수가 있다. 실제 상태가 `LIVE`이고 `now - startedAt < 10초`면 `READY`, 그 밖은 실제 상태다. `startedAt`이 없거나 클라이언트 시계보다 미래여도 최대 10초만 늦춘다. 단위 테스트가 경계(9.9초, 10초, `startedAt` 없음, 미래 시각, `ENDED`)를 확인한다
- [ ] 시청 화면(`BroadcastPage`): 지연 중에는 READY와 같이 보인다. 대기 이미지 또는 "방송 준비 중입니다.", 상태 배지 "방송 준비 중", 경과 시간 없음, "후원하기" 없음, 새 후원 배너 없음이다. 10초가 되면 다음 5초 조회를 기다리지 않고 타이머로 플레이어(`LivePlayer`)로 바뀐다. 가짜 시계 테스트로 확인한다
- [ ] 공개 목록 화면이 같은 함수를 쓴다: 홈 카드의 배지와 정렬(LIVE 먼저)과 LIVE 탭·카테고리 필터, 채널 페이지 "지금 방송 중", 검색 결과, 팔로우 패널의 LIVE 점과 비로그인 "LIVE 중인 방송". 지연 중인 방송은 LIVE 묶음에 들어가지 않고 "방송 준비 중"으로 보인다
- [ ] 송출 화면(`PublishPage`·`ObsPanel`), 시청 화면의 소유자 버튼(`OwnerActions`의 방송 종료), 스튜디오 목록은 실제 상태를 그대로 쓴다. 소유자는 LIVE가 되자마자 방송 종료를 누를 수 있다
- [ ] 문서: `apps/web/CLAUDE.md`의 방송 목록·시청 행, PRD §7.4에 "공개 화면의 LIVE 표시 지연" 한 줄, README 확인 순서 2번과 `docs/VERIFICATION.md` 송출→시청 절의 대기 설명을 고친다

Priority: P1 | Effort: M | Dependencies: none (#248과 같은 파일을 건드리지 않는다. 둘 다 `LivePlayer` 주변이면 #248 머지 뒤 rebase)

- 휴대폰 시계가 서버와 몇 초 어긋나면 지연이 그만큼 길거나 짧아진다. 최대 10초로 묶어 길어지는 쪽만 막는다.
