# Discovery Plan: 방송 카테고리

- **Date**: 2026-11-13
- **Product Stage**: 기존 제품, 실사용자 없음. 기능을 실제로 보는 사람은 공모전 심사자다.
- **Discovery Question**: 마감(2026-11-19) 전에 방송 카테고리를 넣을까? 넣는다면 게임 타이틀 목록을 어떻게 유지할까?
- **PRD 관계**: PRD §8.2 Non-goals에 "카테고리·검색"이 있다. 구현하면 PR 본문에 "PRD §8.2와 어긋남"과 아래 이유를 적는다.

## 도입 이유 (사용자 확인)

외부 게임 DB를 붙이는 이유는 두 가지다.

1. **타이틀 품질**: 게임 목록을 직접 관리하면 신작이 나올 때마다 손으로 갱신해야 한다. 자유 입력만 받으면 "롤/LoL"처럼 표기가 흔들린다.
2. **외부 API 연동 경험(학습 목적)**: 이 목적으로 일부러 넣는다는 것도 그대로 기록한다.

## Selected Design

대분류는 우리 enum이 정하고, **게임일 때만** 게임 타이틀을 고른다(2단 구조).

**2026-11-14 E1 이후 변경**: 타이핑할 때마다 Wikidata를 실시간 검색하던 설계를 버렸다. 대신 게임 목록을 **한 번에 받아 우리 DB에 넣고 우리 DB에서 검색**한다. 실시간 검색은 한 번에 1.3~2.8초가 걸렸고, 요청 간격이 2초여도 429(`retry-after: 2`)가 났기 때문이다.

```
[가져오기 스크립트, 수동 또는 주 1회]
  Wikidata SPARQL 한 번 (P31=Q7889, 한국어 라벨 있는 것)
  → Game 테이블에 upsert { qid, nameKo, nameEn, aliasesKo[] }

[방송 폼]
  우리 API GET /games?q= → Game 테이블에서 nameKo·nameEn·aliasesKo 검색 (외부 호출 없음)

[방송 저장]
  { category, gameQid?, gameName? } 스냅샷. 목록과 시청은 스냅샷만 읽는다.
```

이 구조에서 "주기적 업데이트"는 스크립트를 다시 돌리는 일이다. 사람이 게임 목록을 관리할 필요가 없다. Wikidata가 장애를 일으켜도 다음 가져오기만 미뤄질 뿐, 검색과 방송 생성은 멀쩡하다.

- **Steam**: 한국 주요 게임이 없거나 한국어 검색에 0건이 나온다. `ISteamApps/GetAppList/v2`는 404를 돌려준다. 탈락.
- **Twitch Search Categories / IGDB**: 박스아트가 있다. 대신 Twitch 개발자 앱 등록과 2FA가 필요하다. 한국어 이름은 확인하지 못했다. 사용자가 제외했다.
- **RAWG**: 무료 키와 출처 표기가 필요하다. 시험하지 않았다.
- **Wikidata**: 키가 필요 없고 데이터는 CC0다. 한국어 라벨과 별칭이 있다.
  - 검색 결과에 게임이 아닌 항목이 섞인다(롤빵, 미국 도시 배틀그라운드). P31 분류로 거른다. LoL(Q223341)에는 Q7889가 붙어 있는 것을 확인했다.
  - 박스아트가 없어 텍스트 배지로 간다.
  - 연속 요청에 **429**가 한 번 나왔다.

## E1 결과 (2026-11-14)

한국어 검색어 20개를 wbsearchentities(limit 10)로 검색하고 P31=Q7889로 걸렀다. **20/20에서 맞는 게임이 1위**였다.

- 검색어: 리그 오브 레전드, 롤, 배틀그라운드, 배그, 메이플스토리, 로스트아크, 발로란트, FC 온라인, 마인크래프트, 오버워치, 스타크래프트, 디아블로 4, 던전앤파이터, 엘든 링, 원신, 로블록스, 이터널 리턴, 서든어택, 카트라이더, 하스스톤
- 필터로 걸러진 잡음: 롤빵, 미국 도시 배틀그라운드, 영화 "마인크래프트 무비", e스포츠 리그(Q48004378), 회사(로블록스 코퍼레이션)
- 응답 시간: 검색 1회에 1.2~2.8초(요청 2건). 429 재시도 때문에 한 번은 17초가 걸렸다
- 429: 요청 간격을 2초로 늘려도 5~6회 검색 뒤 막혔다. 간격 10초에서는 막히지 않았다
- SPARQL 일괄 받기: `P31=Q7889`이면서 한국어 라벨이 있는 게임 **6,365건**, 2.7MB, 42초. 위 게임과 "카트라이더 러쉬플러스"까지 포함됐다. LoL 한국어 별칭은 `롤|LOL|League of Legends|리그오브레전드`였다

일괄 받기에 쓴 쿼리 (`https://query.wikidata.org/sparql`, `Accept: application/sparql-results+json`):

```sparql
SELECT ?game ?ko ?en (GROUP_CONCAT(DISTINCT ?alias; separator="|") AS ?aliases) WHERE {
  ?game wdt:P31 wd:Q7889 ;
        rdfs:label ?ko FILTER(LANG(?ko) = "ko")
  OPTIONAL { ?game rdfs:label ?en FILTER(LANG(?en) = "en") }
  OPTIONAL { ?game skos:altLabel ?alias FILTER(LANG(?alias) = "ko") }
} GROUP BY ?game ?ko ?en
```

결론: 데이터 품질은 충분하다. 실시간 호출은 쓸 수 없다. 그래서 일괄로 받아 로컬에서 검색하는 방식으로 바꾼다.
