## Product Requirements Document: 직접 만든 플레이어 컨트롤

**Author**: kh.jeon
**Date**: 2026-11-10
**Status**: 구현 완료 (2026-11-11, 1단계 #56: #57, 2단계 PR #70, 재생 속도 #69: #71)

## 1. Summary

시청 화면의 라이브 플레이어(`LivePlayer`)에서 브라우저 기본 컨트롤(`<video controls>`)을 없애고, Lime 토큰으로 직접 그린 오버레이 컨트롤을 올린다. 재생 엔진(hls.js, iPhone 네이티브 HLS)은 그대로 두고 겉 UI만 바꾼다. 새 의존성은 없다. 다시보기 플레이어(`ReplayPlayer`)는 2단계에서 같은 컨트롤 부품을 재사용해 바꾼다.

## 3. Background

- 지금 플레이어는 브라우저마다 모양이 다른 기본 컨트롤을 쓴다. 나머지 화면은 토큰과 Pretendard로 통일했는데 플레이어만 어울리지 않는다.
- 기본 컨트롤은 라이브에 맞지 않는다. 라이브인데 탐색 바와 시간이 보이고(브라우저마다 다르게), 일시정지했다가 재생하면 방송보다 뒤처졌다는 표시나 따라잡기 버튼이 없다.
- 치지직·트위치도 `controls` 없이 `<video>` 위에 HTML 컨트롤을 올리는 방식이다. 이 프로젝트는 `apps/web/CLAUDE.md` 규칙에 따라 두 서비스의 **배치만** 참고하고 로고·색·아이콘은 쓰지 않는다.
- OME는 영상을 트랜스코딩하지 않고 그대로 내보낸다(`ome/Server.xml`의 `bypass_video`). 화질이 하나뿐이라 화질 선택 메뉴는 필요 없다.
- 마감은 2026-11-19 23:59 KST다. 이 작업은 심사자가 처음 보는 화면의 인상을 바꾸지만, 기능 요구사항(PRD.md)보다 우선하지 않는다.

## 4. Objective

시청 화면의 플레이어가 Lime의 나머지 화면과 같은 디자인으로 보이고, 라이브에 맞는 조작(라이브로 이동)을 제공한다.

| 결과 | 측정 | 목표 |
|---|---|---|
| 디자인 통일 | Chrome·Edge·Safari(Mac)·Android Chrome에서 같은 컨트롤 모양 | 4개 브라우저 모두 같은 모양 (Playwright 스크린샷) |
| 라이브 조작 | 일시정지 후 재생하면 LIVE 표시가 바뀌고 "라이브로 이동"으로 따라잡음 | 따라잡은 뒤 지연이 PRD KR2(5초 이하) 안 |
| 회귀 없음 | 기존 `LivePlayer.test.tsx`와 e2e | 모두 통과, 자동 재생·음소거 시작 동작 유지 |
| 접근성 | 키보드만으로 모든 컨트롤 조작, 버튼마다 이름 | Tab·Space·Enter로 전부 조작 가능 |

## 5. Market Segment(s)

- **시청자 (PC)**: 로그인 없이 링크로 들어와 본다. 소리 켜기, 볼륨, 전체화면을 가장 많이 쓴다.
- **시청자 (모바일)**: 탭으로 컨트롤을 띄우고 숨긴다. iPhone은 전체화면에서 iOS 기본 플레이어로 넘어간다.
- **스트리머 (자기 방송 시청)**: 하울링을 막으려고 음소거로 시작한다(T7). 컨트롤이 바뀌어도 이 동작은 유지된다.
- **공모전 심사자**: 짧은 시간 안에 화면을 보고 완성도를 판단한다. 첫인상에 가장 크게 영향받는 집단이다.

## 6. Value Proposition(s)

**시청자**
- **Who**: 링크로 방송에 들어온 시청자
- **Why**: 방송을 편하게 보고, 놓친 부분 없이 지금 장면을 보고 싶다
- **What before**: 브라우저마다 다른 기본 컨트롤. 일시정지 후에는 뒤처진 줄 모르고 계속 본다
- **How**: 영상 위 오버레이 컨트롤. LIVE 표시가 뒤처지면 회색이 되고, 누르면 라이브로 이동한다
- **What after**: 어느 브라우저에서나 같은 컨트롤로 보고, 한 번 눌러 라이브를 따라잡는다
- **Alternatives**: 새로고침(느리고 음소거 상태로 돌아갈 수 있다), 기본 컨트롤의 탐색 바를 끝까지 끌기(브라우저마다 동작이 다르다)

**심사자**
- **Who**: 공모전 심사자
- **Why**: 제출물이 실제 서비스 수준인지 판단하고 싶다
- **What before**: 플레이어만 브라우저 기본 모양이라 미완성처럼 보인다
- **How**: 나머지 화면과 같은 토큰·글꼴·간격으로 그린 컨트롤
- **What after**: 시청 화면 전체가 하나의 서비스로 보인다
- **Alternatives**: Media Chrome·Vidstack·Plyr 같은 라이브러리. 새 의존성이 생기고, 라이브러리 고유 스타일을 토큰에 맞추려면 덮어써야 해서 쓰지 않는다

## 7. Solution

### 7.1 화면 배치

```
┌─ .player (position: relative, 16:9, --color-video-bg) ──────────┐
│ <video> (controls 없음)                                          │
│                                                                  │
│                       [ ▶ ]  ← 일시정지·자동재생 실패 때만        │
│  [🔇 소리 켜기]  ← 음소거로 시작했을 때만, 왼쪽 위                │
│                                                                  │
│ ── 아래 그라데이션 바 (숨김 규칙 7.3) ─────────────────────────  │
│ ▶  🔈━━━○──  ● LIVE                                      ⛶     │
└──────────────────────────────────────────────────────────────────┘
```

### 7.2 1단계 컨트롤 (LivePlayer)

| 컨트롤 | 동작 |
|---|---|
| 재생/일시정지 | `video.play()`/`pause()`. 영상 빈 곳을 클릭해도 같은 동작 |
| 음소거 | `video.muted` 토글. 아이콘은 음소거·작게·크게 세 가지 |
| 볼륨 | `<input type="range">` 0~1. PC에서 음소거 버튼에 마우스를 올리면 펼친다. 모바일에서는 숨긴다(기기 볼륨을 쓴다). 볼륨 값은 `localStorage`에 기억한다(try/catch). 음소거 여부는 기억하지 않는다(T7·자동재생 규칙을 지키기 위해) |
| LIVE 표시 | 라이브 끝에서 3초 이내면 `--color-live` 점, 그보다 뒤면 회색 점과 "라이브로 이동" 툴팁 |
| 라이브로 이동 | LIVE 표시를 누르면 hls.js는 `hls.liveSyncPosition`, 네이티브는 `seekable.end(last)`로 이동하고 재생 |
| 전체화면 | 컨테이너에 `requestFullscreen()`. 미지원(iPhone)이면 `video.webkitEnterFullscreen()`. 더블클릭도 같은 동작 |
| 소리 켜기 버튼 | 음소거로 시작했을 때(소유자 시작, 자동재생 차단) 왼쪽 위에 크게. 누르면 음소거 해제 후 사라진다 |

아이콘은 인라인 SVG로 직접 그리고 `currentColor`를 쓴다. 색·간격은 `tokens.css` 토큰만 쓰고, 필요한 값(오버레이 그라데이션, 컨트롤 높이 등)은 토큰을 먼저 추가한다.

### 7.3 표시·숨김

- 마우스가 움직이거나 탭하면 보이고, 3초 동안 입력이 없으면 숨긴다. 숨길 때 커서도 숨긴다.
- 일시정지 중, 컨트롤 안에 키보드 포커스가 있을 때, 볼륨 슬라이더를 끄는 중에는 숨기지 않는다.
- 모바일: 첫 탭은 컨트롤만 띄우고 재생 상태를 바꾸지 않는다.
- `prefers-reduced-motion: reduce`면 페이드 없이 바로 바꾼다.

### 7.4 키보드

플레이어에 포커스가 있을 때만 받는다(댓글 입력과 충돌하지 않게).

| 키 | 동작 |
|---|---|
| Space, K | 재생/일시정지 |
| M | 음소거 |
| F | 전체화면 |
| ↑ ↓ | 볼륨 ±10% |

### 7.5 구현 구조

- `components/player/PlayerControls.tsx`: `HTMLVideoElement` ref와 라이브 관련 콜백(`getLiveEdge`, `seekToLive`)을 받는 표시 전용 컴포넌트. 재생 엔진을 모른다.
- `components/player/useMediaState.ts`: `play`·`pause`·`volumechange`·`timeupdate`·`fullscreenchange` 이벤트로 상태를 읽는 훅.
- `LivePlayer`: `controls` 속성을 빼고, hls 인스턴스로 라이브 끝 위치를 계산해 `PlayerControls`에 넘긴다. 로딩·재시도·오류 보고 로직은 바꾸지 않는다.
- 2단계 `ReplayPlayer`는 같은 `PlayerControls`에 탐색 바·시간·속도를 켜는 옵션으로 붙인다.

### 7.6 Assumptions and open questions

| 가정·질문 | 확인 방법 |
|---|---|
| hls.js `liveSyncPosition`으로 이동하면 지연이 5초 이하로 돌아온다 | 로컬 스택에서 일시정지 30초 후 "라이브로 이동", 송출 화면 시계와 비교 |
| iPhone 네이티브 HLS에서 `seekable.end`로 라이브 끝을 구할 수 있다 | 실제 iPhone에서 확인. 안 되면 iPhone은 LIVE 표시만 두고 이동 버튼을 숨긴다 |
| iPhone 전체화면은 iOS 기본 UI로 넘어가도 괜찮다 | 치지직·트위치도 같은 제약. 문서에 한계로 적는다 |
| 기존 테스트가 `controls` 속성이나 기본 UI에 의존하지 않는다 | `LivePlayer.test.tsx` 실행 |

## 8. Release

**1단계 (이번 작업)**: LivePlayer 오버레이 컨트롤 (7.2~7.4). Playwright로 PC·모바일 폭 스크린샷을 남기고 `apps/web/CLAUDE.md` 시청 화면 설명을 고친다.

**2단계**: ReplayPlayer에 같은 컨트롤 + 탐색 바, 현재/전체 시간, 재생 속도(0.5~2배). "1부·2부" 버튼은 그대로 둔다.

**하지 않는 것**
- 화질 선택: OME가 화질 하나만 내보낸다(bypass). 트랜스코딩을 켜면 서버 부담이 커지므로 다루지 않는다.
- 극장 모드: 시청 화면 레이아웃(댓글 열)을 바꿔야 해서 이번 범위에서 뺀다. 마감 전 여유가 있으면 별도 이슈로 한다.
- 라이브 되감기(DVR): 라이브 중 과거 장면 탐색은 하지 않는다.
- iPhone 전체화면에서 직접 만든 컨트롤 표시: 브라우저가 허용하지 않는다.
- 플레이어 라이브러리 도입: 7절 Alternatives 참고.
- 트위치·치지직의 아이콘·색·문구 사용.
