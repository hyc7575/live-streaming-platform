## Product Strategy: 송출 중 대기·자리비움 화면 (Lime 부가기능)

**Date**: 2026-11-11
**Stage**: MVP (마감 2026-11-19 23:59 KST, 남은 8일)
**Author**: kh.jeon

> 결과: 송출 중 대기·자리비움 장면은 구현하지 않았다(`PRD-chat-and-ready.md` 8절). 방송 전 대기는 READY 목록 노출(#90)과 기본 대기 이미지(#63)로 대신했다.

> 범위: 공모전 제출물 안의 기능 하나에 대한 전략이다. `STRATEGY-chat-replay.md`의 "방송 전 채팅"·"READY 목록 노출" 논의를 이 문서가 대신한다. Growth Engine·Defensibility는 짧게 둔다.

### 0. 핵심 관찰

Twitch·치지직의 "곧 시작합니다"·"자리비움" 화면은 플랫폼 기능이 아니다. 스트리머가 OBS에서 장면을 바꿔 **송출 영상 자체를 이미지로 바꾼 것**이다. 플랫폼 입장에서 그 방송은 처음부터 LIVE이고, 채팅도 실시간 채팅이다.

우리 서비스에서 이것이 안 되는 이유는 상태 모델이 아니라 **송출 화면에 "장면 전환"이 없기 때문**이다. 송출 소스는 화면 공유나 카메라뿐이다. 그래서 방송 전 대기는 READY 상태로만 표현되고, READY는 공개 목록에 없다(PRD §7.4). 방송 중 자리비움은 표현할 방법이 아예 없다.

지금 코드에 이미 있는 것:
- 송출 중 영상 트랙 바꾸기: `whipPublisher.replaceTrack`. 화면 공유↔카메라, 전면↔후면 카메라 전환에 쓰고 있다(`PublishPage.tsx`의 `SourcePanel`, `CameraSwitch`).
- 채널 대기 이미지: `User.standbyImageExt`, `/me/standby-image`.

### 1. Vision

스트리머가 자리를 비워도 방송은 이어지고, 시청자는 그 시간에도 채팅으로 서로 이야기한다. 방송 전 10분과 쉬는 시간이 "빈 화면"이 아니라 방송의 일부가 된다.

### 2. Target Segments

| Segment | Pain Level | Current Alternative | Priority |
|---|---|---|---|
| 스트리머 | 높음. 자리를 비우려면 카메라를 켠 채 빈 방을 보여 주거나 방송을 끝내야 한다. 끝내면 다시보기가 두 개로 나뉜다 | 카메라를 천장으로 돌리기, 방송 종료 | 1 |
| 시청자 | 중간. 시작 전에는 방송이 목록에 없어 모일 곳이 없다 | 링크를 받아 READY 화면에서 대기 | 2 |
| 공모전 심사자 | 중간. 실제 방송 플랫폼다운 흐름인지 본다 | 없음 | 2 |

**Primary segment**: 스트리머. 장면 전환은 송출 화면의 기능이다.
**Explicitly not serving**:
- 여러 소스를 겹치는 합성(카메라 + 화면 공유 PIP, 오버레이, 위젯). OBS 영역이고, 매 프레임 합성은 휴대폰 CPU를 쓴다.
- 장면 여러 개 관리, 장면별 이미지 업로드. 이미지 한 장 + 안내 문구로 충분하다.

### 3. Pain Points & Value Created

- **자리비움을 표현할 수 없다**: 카메라를 계속 보내면 빈 방이나 사생활이 노출된다. 끄면 방송이 끝난다. → 이미지 장면으로 바꾸면 카메라 영상은 나가지 않고 방송은 이어진다.
- **시작 전에 모일 곳이 없다**: READY는 목록에 안 보인다. → "대기 장면으로 송출 시작"이면 상태가 LIVE라서 목록에 뜨고 실시간 채팅이 된다. PRD §7.4 목록 규칙은 그대로 둔다.
- **다시보기가 끊긴다**: 쉬려고 방송을 끝내면 녹화가 둘로 나뉜다. → 한 방송, 한 녹화로 이어진다. 대기 구간도 녹화에 남아 다시보기 채팅 동기화(`STRATEGY-chat-replay.md` E·F)와도 맞는다.

### 4. Value Propositions

- **스트리머**: When 밥 먹으러 자리를 비울 때, they want 카메라 영상만 끄고 방송은 이어 두고 싶어 한다, so they can 돌아와서 같은 방송을 계속한다.
- **스트리머**: When 시작 10분 전일 때, they want 대기 화면을 먼저 띄우고 싶어 한다, so they can 시청자가 모인 뒤 본방송을 시작한다.
- **시청자**: When 스트리머가 자리를 비웠을 때, they want 언제 돌아오는지 알고 다른 시청자와 이야기하고 싶어 한다, so they can 나가지 않고 기다린다.

### 5. Strategic Trade-offs

| We Choose | Over | Because |
|---|---|---|
| **송출 영상 자체를 이미지 장면으로 바꾸기** (canvas에 이미지와 문구를 그리고 `canvas.captureStream()` 트랙을 `replaceTrack`으로 보냄) | 시청자 화면에 오버레이만 띄우기 (서버에 `away` 플래그 → 시청 클라이언트가 이미지로 덮음, 송출은 영상 트랙 해제) | 오버레이는 녹화에 남지 않아 다시보기에 정지 화면·검은 화면이 남는다. 영상 트랙을 빼면 LL-HLS가 멈출 수 있다. 서버 상태와 API가 더 필요하다. 송출 영상으로 바꾸면 시청·녹화·썸네일이 저절로 맞는다 |
| 장면을 바꿀 때만 canvas 사용 (본방송은 지금처럼 원본 트랙) | 매 프레임 canvas 합성 | 본방송 중 휴대폰 CPU·배터리 부담이 없다. 이미 있는 `replaceTrack` 경로를 그대로 쓴다 |
| 채널 대기 이미지 한 장 + 장면별 문구("곧 시작합니다" / "잠시 자리를 비웠습니다 · 12분째") | 대기·자리비움 이미지 따로 업로드 | 업로드 API·저장·화면이 두 배가 된다. 문구로 구분해도 시청자는 상황을 안다. 필요하면 나중에 이미지 하나를 더한다 |
| 마이크는 장면과 따로 켜고 끈다. 자리비움에 들어가면 기본으로 끈다 | 장면에 마이크를 묶기 | 대기 장면에서 말을 하거나 음악을 트는 스트리머도 있다. 자리비움에서 마이크가 켜져 있으면 사생활 노출 위험이 있다 |
| READY는 지금처럼 목록에서 숨긴다 | READY "방송 예정" 구역 | 모이는 시간은 대기 장면 LIVE가 맡는다. PRD §7.4를 바꾸지 않는다 |
| 대기 장면 중 썸네일은 그 장면을 그대로 캡처, 종료 후 대표 썸네일은 본방송 장면에서만 고른다 | 대기 중 캡처 중단 | LIVE 카드에 "곧 시작" 장면이 보이는 것이 사실이다(Twitch도 같다). 다만 끝난 방송의 얼굴이 대기 이미지가 되면 안 된다(이전 요청) |

### 6. Key Metrics

공모전이라 사용량 지표가 없다. 인수 기준으로 대신한다.

- **North Star**: 스트리머가 자리비움으로 바꾸고 10분 뒤 돌아와도 방송·녹화가 끊기지 않고 하나로 이어진다.
- **Input**:
  - 장면 전환 후 시청자 화면에 이미지가 보일 때까지 5초 이내 (LL-HLS 지연 포함)
  - 자리비움 중 새로 들어온 시청자가 5초 안에 이미지를 본다 (키프레임 문제 없음)
  - 대기 장면으로 시작한 방송이 공개 목록에 LIVE로 뜬다
- **Health (guardrail)**:
  - 자리비움 중 카메라 영상 0프레임 송출 (사생활)
  - 송출 탭을 백그라운드로 보내도 10분 동안 영상이 멈추지 않는다
  - 본방송 중 CPU·비트레이트 변화 없음 (canvas는 장면 중에만)

### 7. Growth Engine

해당 없음. README "기능 확인"에 "대기 장면으로 시작 → 본방송 → 자리비움 → 복귀 → 종료 후 다시보기 하나로 이어짐"을 넣는다.

### 9. Defensibility

해당 없음. 면접·심사에서 설명할 설계 이유가 남는다: "자리비움을 서버 상태가 아니라 송출 영상으로 표현한 이유 — 시청·녹화·썸네일이 한 경로로 맞는다."

### Strategic Risks

1. **백그라운드 탭에서 canvas가 멈춘다** (가장 큼): 스트리머가 자리를 비우며 탭을 바꾸거나 화면을 끄면 브라우저가 타이머·`requestAnimationFrame`을 늦추거나 멈춘다. canvas에 새 프레임이 없으면 영상이 멈춘다. → 스파이크에서 먼저 확인한다. 대응 후보: Web Worker 타이머로 다시 그리기, 송출 화면에 "이 탭을 열어 두세요" 안내. 휴대폰 화면 잠금은 지금도 송출이 끊기므로 같은 안내를 쓴다.
2. **키프레임**: 정지 이미지는 인코더가 키프레임을 드물게 낼 수 있다. 중간에 들어온 시청자가 오래 검은 화면을 볼 수 있다. → 문구에 경과 시간(초 단위 변화)을 넣어 프레임을 계속 만들고, 스파이크에서 입장 지연을 잰다.
3. **마감**: 스파이크 포함 1.5일이다. 필수 회귀·README(#17)보다 뒤다. 스파이크에서 1·2가 해결되지 않으면 이 기능은 넣지 않고 README에 "향후 과제"로 적는다.
