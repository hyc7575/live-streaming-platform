# 채팅은 실시간 푸시 없이 커서 폴링으로 받는다

방송 전·중 채팅은 WebSocket 같은 실시간 푸시를 쓰지 않는다. 시청 화면이 1초마다 `GET /api/broadcasts/:id/chat?after=<마지막 id>`로 새 메시지만 받는다(#91). 실시간 푸시는 첫 PRD부터 하지 않는 것(PRD §8.2)이었고, 공모전 규모(방송당 채팅 수천 건 이하, 동접 수 명)에서는 1초 폴링으로 충분하다고 보았다. 저장소도 PostgreSQL 한 테이블이고 NoSQL은 쓰지 않는다.

## Considered Options

- **전체 목록 1초 폴링 (#91 이전)**: 방송 중 댓글 패널이 1초마다 전체 목록을 다시 받아, 채팅 1,000건이면 1초마다 1,000건을 받았다. `after` 커서로 바꿔 응답 크기가 새 메시지 수에만 비례하게 했다.
- **WebSocket 푸시**: PRD §8.2에서 뺐다.

## Consequences

- 채팅은 최대 약 1초 늦게 보이고, 채팅 패널을 연 시청자마다 초당 한 번씩 요청한다. 시청자가 크게 늘면 다시 판단해야 한다.
- 채팅과 댓글은 다른 테이블이다(`ChatMessage`, `Comment`). 채팅은 고치지 않아 커서가 단순하다.
