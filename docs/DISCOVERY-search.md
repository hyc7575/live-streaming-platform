# Discovery Plan: 방송 검색

- **Date**: 2026-11-15
- **Product Stage**: 기존 제품, 실사용자 없음. 기능을 실제로 보는 사람은 공모전 심사자다.
- **Discovery Question**: 마감(2026-11-19) 전에 검색을 헤더로 옮길까? 옮긴다면 서버 검색 API까지 만들까?
- **PRD 관계**: PRD §8.2는 "서버 쪽 검색"을 하지 않는다고 정했다. 구현하면 PR 본문에 "PRD §8.2와 어긋남"과 아래 이유를 적는다.

## 출발점

- 지금 검색은 홈 탭이 받아 온 목록(`PUBLIC_LIST_LIMIT` 100개) 안에서 제목·닉네임·게임 이름을 브라우저가 거른다. API를 부르지 않는다.
- 사용자는 트위치·치지직처럼 검색창을 헤더 가운데에 두고 싶다. 헤더에 있는 검색은 서비스 전체 검색처럼 보인다. 그래서 사용자는 서버 검색 API부터 만들기로 했다.
- 공모 원문에는 검색이 필수에도 선택(가산점)에도 없다. 점수에 닿는 길은 "방송 목록" 화면의 완성도뿐이다.

## Ideas Explored

| # | 아이디어 | 결과 |

| 2 | 서버 검색 API: 제목·닉네임·게임 이름, 상태를 가리지 않고 다시보기 포함 | 채택 |

뺀 것: 인기 검색어, `pg_trgm`, 전문 검색. 방송이 수십 개 규모라 효과를 보일 수 없다.

**핵심 판단**: 이 규모에서 서버 검색으로 달라지는 점은 결과 범위가 아니다. 클라이언트 필터로는 못 내는 **새 결과 종류**(스트리머, 게임 별칭, 탭을 가리지 않는 통합 결과)다. 2는 3·4를 위한 수단이다.

## 실험 결과 (2026-11-15)

### E1 목록 규모 (A2)

로컬 개발 DB(main의 API, :3000)에서 공개 API를 불렀다.

| 요청 | 건수 |
|---|---|
| `GET /api/broadcasts` (전체) | 100 (상한) |
| `GET /api/broadcasts?status=ENDED` | 100 (상한) |
| `GET /api/broadcasts?status=LIVE` | 0 |
| `GET /api/replays` | 83 |

e2e 실행이 쌓은 방송 때문에 로컬에서는 상한이 이미 결과를 자른다. 배포 서버 URL은 문서에 없어 확인하지 못했다. 심사 규모(방송 3~6개)에서는 자르지 않을 것으로 본다.

### E2 게임 별칭 (A3)

`apps/api/data/games.json` 6,365건에서 흔한 줄임말 10개를 찾았다.

| 검색어 | 포함 일치 게임 수 | 별칭 완전 일치 |
|---|---|---|
| 롤 | 30 | 리그 오브 레전드 |
| 배그 | 2 | 배틀그라운드 |
| 메이플 | 3 | 없음 |
| 발로 | 1 | 없음 |
| 옵치 | 0 | 없음 |
| 피파 | 7 | 없음 |
| 스타 | 158 | 없음 |
| 마크 | 8 | 없음 |
| 로아 | 1 | 없음 |
| 오버워치 | 2 | 없음 |

- 포함 일치로 별칭을 쓰면 잡음이 크다. "롤"은 게임 30개에, "스타"는 158개에 걸린다.
- 그래서 별칭은 **완전 일치 토큰**만 쓴다. 방송의 `gameQid`가 가리키는 `Game.searchText`에서 검색어와 똑같은 토큰이 있으면 그 방송을 찾는다.
- 효과는 좁다. 다만 인수 시나리오 24가 쓰는 검색어 "롤"에 정확히 맞는다.
- 게임 이름 부분 일치("리그")는 지금 클라이언트 필터도 `gameName`으로 하고 있다.

### E3 360px 헤더 (A4)

워크트리 웹 서버(:5188)를 360×740으로 열고 헤더 자식 요소의 폭을 쟀다. 헤더 좌우 여백은 12px, 요소 사이 간격도 12px이다.

| 상태 | 로고 | 메뉴 | 계정 | 남는 폭 |
|---|---|---|---|---|
| 비로그인 | 53 | 59 (방송 목록) | 137 (회원가입·로그인) | 63px |
| 로그인 | 53 | 178 (방송 목록·팔로잉·내 방송, 간격 16) | 60 (닉네임은 숨김) | 21px |

- 32px 아이콘 버튼과 간격 12px이 들어가려면 44px가 필요하다. 로그인 상태에서 23px가 모자란다.
- 메뉴 간격 16px를 8px로 줄이면(링크 셋, 간격 둘: −16px) 7px가 더 모자란다. 헤더 간격 12px을 8px로 줄이면 맞는다(간격 셋: −12px).
- 넓은 화면(480px 초과)의 가운데 입력창은 구현 후 측정한다(E6).

### E4 스트리머 데이터 재사용 (A9)

`GET /api/streamers/:id`의 `StreamerProfile`(닉네임, 프로필 이미지, 팔로워 수, `liveBroadcastId`)과 웹의 `channelPath`가 이미 있다. 검색 결과의 스트리머 항목은 같은 모양을 목록으로 돌려주면 된다.
