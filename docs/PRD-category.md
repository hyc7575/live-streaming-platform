## 1. Summary

방송에 대분류(게임·소통·음악·공부/작업·스포츠·기타)를 붙인다. 게임 방송이면 게임 타이틀도 붙인다. 시청자는 목록에서 카테고리로 방송을 거른다.

게임 타이틀은 사람이 관리하지 않는다. 한국어 이름이 있는 비디오 게임 목록을 Wikidata에서 일괄로 받아 저장소에 스냅샷 파일로 두고, 우리 DB에서 검색한다. 서비스가 도는 동안에는 외부 API를 부르지 않는다.

근거는 [DISCOVERY-broadcast-category](./DISCOVERY-broadcast-category.md)다.

> **PRD §8.2와 어긋남**: PRD §8.2는 "카테고리·검색"을 첫 버전에서 하지 않는다고 정했다. 이 문서가 그중 카테고리를 들인다. 이유는 3장 마지막 두 항목이다. 구현 PR은 본문에 이 사실을 쓰고 §8.2를 고친다.

## 3. Background

- 방송에는 제목과 설명만 있다(`Broadcast.title`, `description`). 홈 목록은 상태 탭(LIVE·준비 중·종료·다시보기)과, 받아 온 목록 안에서의 제목·닉네임 검색(`?q=`)만 있다. 무슨 방송인지는 제목을 읽어야 안다.
- 치지직·트위치·SOOP은 모두 방송에 카테고리를 붙이고, 게임 방송은 게임 타이틀까지 붙인다. 심사자에게 익숙한 화면 요소다.
- **게임 타이틀은 목록 관리가 문제다.** 직접 만든 목록은 신작이 나올 때마다 손으로 고쳐야 한다. 자유 입력은 "롤/LoL/리그오브레전드"처럼 표기가 흔들린다.
- **외부 게임 DB 시험 결과** (2026-11-13~14, DISCOVERY 문서):
  - Steam은 한국어 검색에서 LoL·메이플스토리·발로란트가 0건이었다.
  - Twitch·IGDB는 개발자 앱 등록이 필요해 제외했다.
  - Wikidata는 한국어 검색어 20개 모두 맞는 게임이 1위였다.
  - 다만 Wikidata 실시간 검색은 1회에 1.2~2.8초가 걸렸고, 요청 간격이 2초여도 429가 났다.
  - SPARQL로 일괄 받기는 6,365건, 2.7MB, 42초였다(쿼리 제한 60초).
- **들이는 이유 (사용자 확인)**: ① 게임 목록을 사람이 갱신하지 않으면서 타이틀 표기를 통일한다. ② 외부 데이터 연동 경험을 쌓는다(학습 목적임을 그대로 적는다).
- 공모 원문에는 카테고리가 필수에도 선택(가산점)에도 없다. 점수에 닿는 길은 "방송 정보 등록·수정"과 "방송 목록" 화면의 완성도뿐이다.
- 마감은 2026-11-19 23:59 KST이고, 11/19는 신규 기능 금지다.

## 4. Objective

심사자가 방송을 만들 때 카테고리와 게임을 5초 안에 고르고, 목록에서 카테고리로 방송을 거른다. 이 기능이 외부 서비스 장애로 서비스를 멈추게 하지 않는다.

| Key Result | 측정 | 목표 |
|---|---|---|
| KR1. 인수 시나리오 22~25 통과 | 8.3을 배포 URL에서 수행 | 100% |
| KR2. 게임 검색 품질 | E1 검색어 20개로 `GET /api/games` 자동 테스트 (스냅샷 데이터) | 20개 모두 1위 |
| KR3. 검색 속도 | 배포 서버에서 `GET /api/games?q=리그` 10회 | 모두 200ms 이하 |
| KR4. 외부 의존 0 | API 런타임 코드가 Wikidata를 부르지 않는다 (가져오기 스크립트만 부른다) | 런타임 호출 0건 |
| KR5. 인가 | `PATCH /broadcasts/:id`의 새 필드 × 비로그인/타인/본인 자동 테스트 | 401/403/200 |

## 6. Value Proposition(s)

**스트리머**
- **Who**: 방송을 만들거나 수정하는 로그인 사용자
- **Why**: 제목에 "[롤]"을 붙이지 않고도 무슨 방송인지 알리고 싶다
- **What before**: 제목과 설명만 쓸 수 있다
- **How**: 방송 생성·수정 폼에서 카테고리 칩을 고른다. "게임"이면 게임 입력칸에 "롤"을 치고 "리그 오브 레전드"를 고른다
- **What after**: 카드와 시청 화면에 "게임 · 리그 오브 레전드" 배지가 붙는다
- **Alternatives**: 치지직 카테고리, 트위치 카테고리

**시청자**
- **Who**: 홈 목록에 들어온 시청자
- **Why**: 게임 방송만, 또는 소통 방송만 보고 싶다
- **What before**: 제목을 하나씩 읽거나, 검색창에 게임 이름을 쳐서 제목에 그 이름이 있기를 바란다
- **How**: 상태 탭 아래 카테고리 칩을 누른다. 검색창에 게임 이름을 치면 게임 타이틀로도 찾는다
- **What after**: 고른 카테고리의 방송만 남고, URL을 공유해도 같은 필터가 걸린다
- **Alternatives**: 치지직 카테고리 탐색, 트위치 Browse

**심사자**
- **Who**: 테스트 계정으로 방송을 만들어 보는 공모전 평가자
- **Why**: 방송 정보 등록이 실제 서비스처럼 동작하는지 본다
- **What before**: (새 기능이라 없음)
- **How**: README "기능 확인"의 카테고리 절차를 따른다
- **What after**: 등록 → 목록 배지 → 필터가 한 흐름으로 확인된다
- **Alternatives**: 없음

## 7. Solution

### 7.1 데이터 모델

- `enum BroadcastCategory { GAME TALK MUSIC STUDY SPORTS ETC }`. 화면 이름은 게임·소통·음악·공부/작업·스포츠·기타다.
- `Broadcast.category BroadcastCategory @default(ETC)`. 마이그레이션은 기존 방송을 `ETC`로 채운다. null을 두지 않아 필터가 단순하다.
- `Broadcast.gameQid String?`, `Broadcast.gameName String?`. 방송을 저장할 때의 **스냅샷**이다. `Game`과 외래 키를 걸지 않는다. 다음 가져오기에서 그 게임이 빠져도 방송은 그대로 보여야 하기 때문이다.
- `model Game { qid String @id; nameKo String; nameEn String?; aliasesKo String[]; searchText String; updatedAt DateTime }`.
  - `searchText`는 nameKo·nameEn·aliasesKo를 공백 없이 소문자로 이은 값이다. 그래서 "리그오브레전드"로 쳐도 "리그 오브 레전드"를 찾는다.
- 스냅샷 파일 `apps/api/data/games.json`: `[{qid, nameKo, nameEn, aliasesKo}]`. 필요한 필드만 남겨 저장소에 커밋한다. Wikidata 데이터는 CC0다.

### 7.2 게임 목록 가져오기

| 명령 | 하는 일 | 외부 호출 |
|---|---|---|
| `pnpm --filter api games:refresh` | Wikidata SPARQL 1회 → `games.json`을 새로 쓴다. 0건이거나 HTTP가 실패하면 파일을 건드리지 않고 0이 아닌 코드로 끝난다 | 있음 (수동) |
| `pnpm --filter api db:seed` (기존) | `games.json`을 `Game`에 upsert한다. 파일에 없는 행은 지운다 | 없음 |

- 배포 서버는 Wikidata에 기대지 않는다. 배포는 커밋된 파일로만 시드한다. 42초 걸리는 쿼리가 60초 제한에 걸려도 배포는 실패하지 않는다.
- "주기적 업데이트"는 `games:refresh`를 돌려 커밋하는 일이다. 첫 버전은 수동으로 한다(8.2).
- 요청에는 Wikimedia User-Agent 정책에 맞는 설명이 담긴 UA를 쓴다(E4).

### 7.3 API와 인가

| 행위 | 비로그인 | 로그인(타인) | 본인 |
|---|---|---|---|
| `GET /api/games?q=` 게임 검색, 최대 10건 | 401 | 허용 | 허용 |
| `POST /api/broadcasts` `{..., category?, gameQid?, gameName?}` | 401 | — | 허용 |
| `PATCH /api/broadcasts/:id` 같은 필드 | 401 | 403 | 허용 |
| `GET /api/broadcasts`, `/broadcasts/:id`, `/replays` 응답에 `category`, `game: {qid, name} \| null` | 허용 | 허용 | 허용 |

- `GET /api/games`
  - 로그인을 요구한다. 쓰는 곳이 방송 폼뿐이고, 공개 엔드포인트로 두면 남용을 막을 장치가 따로 필요하다.
  - `q`는 공백을 뺀 뒤 1~50자다. 아니면 400이다.
  - 검색은 `searchText`에 대한 `ILIKE`다(6천여 행이라 인덱스가 필요 없다). 순서는 nameKo 완전 일치 → 별칭 완전 일치 → 앞부분 일치 → 포함 → 이름 길이가 짧은 순이다.
- 게임 필드 규칙. 서버가 검증하고, 순서는 401 → 403 → 400이다.
  - `category`가 `GAME`이 아니면 `gameQid`·`gameName`을 보낼 수 없다(400). 수정에서 카테고리를 `GAME`이 아닌 것으로 바꾸면 서버가 게임 필드를 비운다.
  - `gameQid`를 보내면 `Game`에 있어야 한다(없으면 400). `gameName`은 **서버가** `Game.nameKo`로 채운다. 클라이언트가 보낸 이름은 쓰지 않는다.
  - `gameQid` 없이 `gameName`만 보내면 "직접 입력"이다. 공백을 뺀 뒤 1~50자다. 목록에 없는 게임(E1의 "카트라이더 슈퍼러쉬")을 받는 길이다.
  - 게임은 선택 사항이다. `GAME`이면서 게임이 없어도 된다.
- 수정은 제목과 같이 **모든 상태**(READY·LIVE·ENDED)에서 할 수 있다. LIVE 중에 게임을 바꾸는 것은 실제 방송에서 흔하다.

### 7.4 화면

- **방송 생성·수정 폼** (`NewBroadcastPage`, `EditBroadcastPage`)
  - 제목 아래 카테고리 칩 6개(라디오 그룹)를 둔다. 기본값은 "기타"다.
  - "게임"을 고르면 게임 입력칸이 열린다. 콤보박스 패턴이고, 300ms 디바운스 뒤 `/api/games`를 부른다.
  - 후보 아래에 늘 "'<입력값>' 직접 입력" 항목이 있다.
  - 검색이 실패해도 폼은 막히지 않는다. "직접 입력"만 남는다.
- **방송 카드** (`BroadcastGrid`): 제목 위에 배지 "게임 · 리그 오브 레전드" 또는 "소통"을 단다. "기타"는 배지를 달지 않는다(잡음).
- **시청 화면** (`BroadcastPage`): 제목 옆에 같은 배지를 단다.
- **홈 목록** (`HomePage`)
  - 상태 탭 아래 카테고리 칩 줄을 둔다: 전체 · 게임 · 소통 · 음악 · 공부/작업 · 스포츠 · 기타.
  - URL은 `?category=GAME`이고, `status`·`q`와 함께 쓴다.
  - 걸러내기는 `q`처럼 받아 온 목록 안에서 클라이언트가 한다. 서버 쿼리는 바꾸지 않는다.
  - 검색어 `q`가 `gameName`도 찾는다.
  - 고른 카테고리에 방송이 없으면 "'게임' 방송이 없습니다."를 보여 준다.
- UI 작업 전 `apps/web/CLAUDE.md`를 읽는다.

### 7.5 Assumptions and open questions

- 대분류 6개로 충분하다고 가정한다. 바꾸려면 enum 마이그레이션이 필요하다.
- `ILIKE` 전체 스캔이 6천여 행에서 KR3(200ms)를 지킨다고 가정한다. 넘으면 `pg_trgm` 인덱스를 단다.
- **E4 (미확인)**: Wikimedia API 이용 정책. 수동 실행, 요청 1건, 설명이 담긴 UA면 문제없을 것으로 본다. 구현 PR 전에 문서로 확인한다.
- **E5 (미확인)**: 방송 6개 목록에서 배지와 칩이 완성도로 보이는가. 1단계를 머지한 뒤 스크린샷으로 판정한다.
- 공개 API(`/api/games` 비로그인 허용)는 카테고리 탐색 페이지를 만들 때 다시 정한다.

### 8.3 인수 시나리오 (PRD 8.3에 이어 붙인다)

22. A로 로그인 → 방송 만들기 → "소통"을 골라 저장 → 홈 카드와 시청 화면에 "소통" 배지가 있다. 카테고리를 고르지 않은 방송에는 배지가 없다
23. 비로그인으로 홈 → "게임" 칩 → 게임 방송만 남고 URL에 `category=GAME`이 있다. 그 URL을 새 탭에서 열어도 같다. 이어서 "종료" 탭을 눌러도 카테고리 필터가 유지된다
24. A가 방송 수정 → "게임" → 게임칸에 "롤" → 후보 1위 "리그 오브 레전드" 선택 → 저장 → 배지 "게임 · 리그 오브 레전드". 헤더 검색에 "리그"를 치면 제목에 "리그"가 없어도 결과 화면에 이 방송이 나온다. LIVE 중에도 같은 수정이 된다
25. 게임칸에 목록에 없는 "카트라이더 슈퍼러쉬" → "직접 입력" → 저장 → 배지에 그대로 보인다. 카테고리를 "음악"으로 바꿔 저장하면 게임 배지가 사라진다. B로 A의 방송에 `PATCH` → 403
