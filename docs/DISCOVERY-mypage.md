## Discovery Plan: 채널 페이지와 마이페이지

**Date**: 2026-11-13
**Product Stage**: 기존 제품 (공모전 제출물, 마감 2026-11-19 23:59 KST, 11/19는 신규 기능 금지)
**Discovery Question**: 치지직·트위치의 프로필·마이페이지 기능 중 무엇을 남은 5일 안에 넣어야 심사에서 손해 없이 이득을 보나?

### Ideas Explored

치지직·트위치는 공개 채널 페이지, 시청자 마이페이지(계정·지갑·내역), 스튜디오(채널 운영) 세 곳으로 나눈다. 우리는 스튜디오(`/studio`, `/studio/channel`)와 팔로잉(`/following`)만 있다. 메뉴 구성은 웹 자료가 부족해 기존 지식으로 정리했다.

| # | 아이디어 | 대상 | 지금 있는 데이터 |
|---|---|---|---|
| 1 | 공개 채널 페이지 `/channels/:id` | 시청자 | `Broadcast.streamerId`, `Follow`, 대기 이미지 |
| 2 | 라임 내역 (충전·후원 원장) | 시청자 | `LimeLedger` |
| 3 | 내가 보낸 후원 | 시청자 | `Donation.donorId` |
| 4 | 받은 후원 합계 (전체 방송) | 스트리머 | 방송별 합계만. 스트리머 단위는 없음 |
| 5 | 팔로워 수·목록 | 스트리머 | `Follow` (`@@index([streamerId])`) |
| 6 | 프로필 편집 (닉네임·소개·프로필 이미지) | 둘 다 | `nickname`만. 이미지 규칙은 `images/image-rules.ts` 재사용 |
| 7 | 비밀번호 변경·탈퇴 | 둘 다 | 선택 안 함 |
| 8 | 시청 기록 | 시청자 | 선택 안 함 |
| 9 | 채팅 관리(차단·매니저) | 스트리머 | 선택 안 함 (L) |
| 10 | 방송 통계 | 스트리머 | 선택 안 함 (시청자 수 집계 없음) |

### Selected Ideas for Validation

1~6. 데이터가 대부분 이미 있고, 마이페이지와 채널 페이지라는 두 빈 곳을 채운다.

### 검증 결과 (2026-11-13, 문서·코드 대조)

- **A1 공모 원문 대조**: 선택 요구사항은 댓글·도네이션·녹화 셋뿐이고 프로필·마이페이지는 없다. 기여 경로는 두 가지뿐이다. ① 평가 기준 "인증 및 인가: 사용자별 접근 권한"의 근거가 늘어난다. 새 `me/*` API마다 401과 "내 것만" 규칙이 생긴다. ② 도네이션 "후원 내역과 합계"의 완성도가 올라간다(보낸 후원·받은 후원). → **범위를 인가와 후원에 닿는 것 위주로 줄인다.**
- **A3 스키마 대조**: `Donation`에는 스트리머 컬럼이 없다. 스트리머는 `Broadcast.streamerId`로만 찾는다. #114 이후 방송을 지우면 `broadcastId`가 null이 되어, 그 후원이 어느 스트리머의 것이었는지 알 수 없다. PRD §7.3의 "`Broadcast.streamerId`로 충분하다"는 #114 이후 맞지 않는다. → **4번을 하려면 `Donation.recipientId`를 추가하고, 지워지지 않은 방송에서 값을 채우는 마이그레이션이 필요하다.** 이미 방송이 지워진 후원은 되살릴 수 없다.
- **A4 README 대조**: README 373행은 로그인하면 "헤더에 '스트리머 A'가 보인다"고 확인하게 한다. 시드는 수동으로만 돌기 때문에, 심사자 한 명이 A의 닉네임을 바꾸면 다음 심사자의 README 절차가 어긋난다. → **테스트 계정은 닉네임 변경을 서버에서 거절한다.** 아니면 6번에서 닉네임을 빼고 소개·이미지만 바꾸게 한다.
- **A7**: `Donation.broadcast`가 null이면 "삭제된 방송"으로 표시한다. #114가 같은 경우를 `BROADCAST_DELETED`로 이미 다룬다.
- **A9**: `IMAGE_RULES.standby`(JPEG·PNG·WebP, 2MB, 매직 바이트)와 `@ImageUpload` 데코레이터를 그대로 쓴다.

### Decision Framework

- E2에서 남는 시간이 1.5일 이상이면 1~6번을 PRD 범위대로 진행한다.
- E2에서 남는 시간이 1.5일보다 적으면 2·3·5번(조회 API와 마이페이지 한 화면)만 한다. 1·4·6번은 non-goal로 미룬다.
- 4번은 `recipientId` 마이그레이션까지 같이 할 때만 넣는다. 마이그레이션 없이 `Broadcast` 조인만으로 합계를 내면 방송을 지울 때마다 합계가 줄어드는 버그를 출시하게 된다.
- E4에서 실패하면 진입점을 고친다. 기능을 더하지 않는다.
