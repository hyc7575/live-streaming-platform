## 1. Summary

치지직·트위치에 있는 "남이 보는 내 채널"과 "나만 보는 내 정보" 화면이 우리에게는 없다. 이미 쌓이는 데이터(팔로우, 라임 원장, 후원)를 보여주는 화면 세 곳을 만든다.

- **A. 마이페이지 `/me`**: 라임 충전·사용 내역, 내가 보낸 후원
- **B. 스튜디오 보강**: 팔로워 수·목록, 받은 후원 합계(모든 방송)
- **C. 공개 채널 페이지 `/channels/:id`**: 프로필, 팔로워 수, LIVE 여부, 지난 방송·다시보기, 팔로우
- **D. 프로필 편집**: 소개, 프로필 이미지, 닉네임(테스트 계정 제외)

근거는 [DISCOVERY-mypage](./DISCOVERY-mypage.md)다.

## 3. Background

- 라임 잔액은 보이지만(`GET /me/lime`) 그 잔액이 어떻게 나왔는지 볼 곳이 없다. `LimeLedger`가 `balanceAfter`까지 기록하는데 화면이 없다. 보낸 후원도 방송별 내역에 흩어져 있어 한곳에서 볼 수 없다.
- 스트리머는 방송별 후원 합계만 본다. 내 팔로워 수와 목록도 볼 수 없다.
- 방송 카드와 시청 화면의 스트리머 닉네임은 링크가 아니다. 그 스트리머의 다른 방송을 모아 보는 화면이 없다.
- **공모 원문에는 프로필·마이페이지가 없다.** 이 기능이 점수에 닿는 길은 두 가지뿐이다. 하나는 평가 기준 "인증 및 인가"로, 새 `me/*` API마다 401과 "내 것만" 규칙이 생긴다. 다른 하나는 도네이션 "후원 내역과 합계"의 완성도다. 그래서 범위를 후원·인가에 닿는 기능 위주로 잡고, 순서도 그 기준으로 정한다.
- **#114 이후 후원을 스트리머 단위로 합산할 수 없다.** `Donation`에는 스트리머 컬럼이 없고 `Broadcast.streamerId`로만 스트리머를 찾는다. 방송을 지우면 `broadcastId`가 null이 되어 받은 사람을 잃는다. PRD §7.3의 "후원 대상 스트리머는 `Broadcast.streamerId`로 충분하다"는 더는 맞지 않는다.
- **여러 심사자가 테스트 계정을 함께 쓴다.** README는 로그인 뒤 "헤더에 '스트리머 A'가 보인다"를 확인하게 한다. 시드는 수동으로만 돌기 때문에, 한 심사자가 A의 닉네임을 바꾸면 다음 심사자의 절차가 어긋난다.
- 마감은 2026-11-19 23:59 KST이고, 11/19는 신규 기능 금지다.

## 6. Value Proposition(s)

**시청자**
- **Who**: 라임을 충전해 후원한 로그인 사용자
- **Why**: 잔액이 왜 이 값인지, 누구에게 얼마를 보냈는지 확인하고 싶다
- **What before**: 잔액 숫자만 보인다. 후원은 방송마다 들어가 봐야 한다
- **How**: 헤더 닉네임 → "마이페이지" → "라임 내역"·"보낸 후원" 탭
- **What after**: 충전·후원이 시간순으로 보이고, 각 행 뒤 잔액이 현재 잔액으로 이어진다
- **Alternatives**: 치지직 치즈 내역, 트위치 Bits 사용 내역

**스트리머**
- **Who**: 방송을 여러 번 한 스트리머
- **Why**: 지금까지 받은 후원과 나를 팔로우한 사람을 알고 싶다
- **What before**: 방송별 후원 합계만 보이고, 방송을 지우면 그 후원이 어디에도 안 보인다
- **How**: 스튜디오 → "후원"·"팔로워" 탭
- **What after**: 모든 방송의 후원 합계와 내역(지운 방송 포함), 팔로워 수와 목록을 본다
- **Alternatives**: 치지직 스튜디오 수익 내역, 트위치 크리에이터 대시보드

**처음 온 시청자**
- **Who**: 링크로 방송 하나에 들어온 비로그인 시청자
- **Why**: 이 스트리머가 어떤 방송을 해 왔는지 보고 싶다
- **What before**: 닉네임을 눌러도 아무 일이 없다. 목록 검색창에 닉네임을 넣어야 한다
- **How**: 시청 화면·카드의 닉네임 → 채널 페이지
- **What after**: 프로필, 지금 LIVE 여부, 지난 방송·다시보기를 한 화면에서 보고 팔로우한다
- **Alternatives**: 치지직 채널 홈, 트위치 채널 페이지

**심사자**
- **Who**: 테스트 계정을 함께 쓰는 공모전 평가자
- **Why**: 앞 사람이 바꾼 상태 때문에 README 절차가 틀어지면 안 된다
- **What before**: (새 기능이라 없음)
- **How**: 테스트 계정은 닉네임 변경이 서버에서 거절된다
- **What after**: README의 "스트리머 A"·"사용자 B"가 늘 그대로다
- **Alternatives**: 심사자마다 계정 발급 (README 절차가 길어진다)

## 7. Solution

### 7.1 데이터 모델

- `Donation.recipientId`(`Uuid?`, `User` 관계 `onDelete: SetNull`)를 추가한다. 후원을 만들 때 `Broadcast.streamerId`를 복사한다. 마이그레이션은 `broadcastId`가 남은 행을 방송의 `streamerId`로 채운다. 이미 방송이 지워진 행은 받은 사람을 알 수 없어 null로 남는다. 인덱스는 `(recipientId, status, approvedAt)`, `(donorId, status, approvedAt)`이다.
- `User.bio`(`String @default("")`, 0~200자)를 추가한다.
- `User.avatarExt`·`avatarUpdatedAt`를 추가한다. 대기 이미지와 같은 방식이고, 파일은 `users/<id>/avatar.<ext>`다.

### 7.2 API와 인가

| 행위 | 비로그인 | 로그인(타인) | 본인 |
|---|---|---|---|
| `GET /api/me/lime/ledger` 라임 원장, 최근 50건 | 401 | — | 내 것만 |
| `GET /api/me/donations` 보낸 후원 (PAID), 최근 50건 | 401 | — | 내 것만 |
| `GET /api/me/received-donations` 받은 후원 합계·건수·최근 50건 | 401 | — | 내 것만 |
| `GET /api/me/followers` 팔로워 수·목록 | 401 | — | 내 것만 |
| `GET /api/streamers/:id` 공개 프로필 (닉네임·소개·이미지·팔로워 수·LIVE 방송 id) | 허용 | 허용 | 허용 |
| `GET /api/streamers/:id/broadcasts` 공개 방송 목록 (공개 목록과 같은 상태 범위) | 허용 | 허용 | 허용 |
| `PATCH /api/me/profile` `{nickname?, bio?}` | 401 | — | 허용. 테스트 계정의 닉네임 변경은 403 "테스트 계정은 닉네임을 바꿀 수 없습니다." |
| `PUT`·`DELETE /api/me/avatar` | 401 | — | 허용 |

- 경로에 사용자 id가 없는 `me/*`는 로그인한 본인 것만 읽고 쓰므로 403 경우가 없다. 기본 대기 이미지와 같은 규칙이다. 테스트 계정 판정만 예외적으로 403을 쓴다.
- `streamers/:id`: UUID가 아니면 400, 없으면 404다. 팔로워 **목록**은 공개하지 않고 수만 공개한다.
- 보낸 후원의 방송이 지워졌으면 `broadcast: null`로 내려가고 화면에는 "삭제된 방송"을 표시한다. 받은 사람 닉네임은 `recipientId`로 보인다.
- 프로필 편집 검증 순서는 401 → 400(본문) → 403(테스트 계정 닉네임)이다. 닉네임 규칙은 가입과 같다(`nicknameSchema`, 1~20자). 아바타는 `IMAGE_RULES.standby`를 그대로 쓴다.
- 테스트 계정 판정은 `TEST_ACCOUNT_*_EMAIL`(시드와 같은 값)과 이메일이 같은지로 한다.

### 7.3 화면

- **헤더**: 로그인하면 닉네임(프로필 원과 함께)이 메뉴가 된다(마이페이지, 내 채널 보기, 로그아웃).
- **영역 메뉴**: 스튜디오와 마이페이지는 시청하는 곳이 아니라 내 작업 공간이라, 왼쪽에 팔로우 패널 대신 그 영역의 메뉴를 둔다. 좁은 화면(1024px 미만)에서는 헤더 아래 탭 줄이다. 처음에는 화면 위쪽 탭으로 썼으나 구현 중 사용자 판단으로 바꿨다.
- **`/me`**: 메뉴 "라임 내역"(`/me`)·"보낸 후원"(`/me/donations`)·"프로필"(`/me/profile`). 라임 내역 위에 현재 잔액과 "충전하기"가 있다.
- **스튜디오**: 메뉴 "내 방송"·"내 채널"·"후원"(`/studio/donations`)·"팔로워"(`/studio/followers`).
- **`/channels/:id`**: 프로필 이미지(없으면 닉네임 첫 글자), 닉네임, 소개, 팔로워 수, 팔로우 버튼(본인 제외), LIVE면 "지금 방송 중" 카드, 그 아래 방송 목록(`BroadcastGrid` 재사용).
- **진입점**: 방송 카드·시청 화면·팔로우 패널의 닉네임을 `/channels/:id` 링크로 바꾼다.

### 7.4 Assumptions and open questions

- **E2 일정 산정(결정됨)**: 2026-11-13 사용자가 #8·#17·#105를 빼고도 11/18까지 1.5일 이상 남는다고 판정했다. 1~4단계를 모두 진행했다.
- **닉네임 편집(결정됨)**: "테스트 계정만 거절"로 구현했다. 사용자가 README를 닉네임에 기대지 않게 고치는 안을 물었으나, 심사자가 목록 카드·팔로우 패널·시드 댓글에서 A를 닉네임으로 알아보고 공유 계정에 남은 닉네임 문제도 풀리지 않아 기본안을 유지했다(#120 댓글). 같은 닉네임을 그대로 보내는 것은 허용해 한 양식으로 소개만 저장할 수 있다.
- 프로필 이미지·소개는 테스트 계정도 바꿀 수 있다고 가정한다. 다른 심사자가 봐도 README 절차가 깨지지 않는다.
- 최근 50건으로 충분하다고 가정한다. 테스트 데이터 규모에서 페이지네이션은 이득이 없다.
- "PRD §7.3과 어긋남"(`Donation`에 `recipientId` 추가)은 #122 본문에 쓰고 §7.3을 고쳤다. 마이그레이션 전에 방송이 이미 지워진 후원은 받은 사람을 알 수 없어 받은 후원 합계에서 빠진다.

## 8. Release

### 8.1 순서와 컷 규칙

공모 평가에 닿는 순서로 나눈다. 단계마다 README "기능 확인"을 함께 쓴다(T13).

| 단계 | 내용 | 완료 기준 |
|---|---|---|
| 1 | A 마이페이지(라임 내역·보낸 후원), B 팔로워, 헤더 메뉴 | 시나리오 17·18, 인가 테스트 |
| 2 | `recipientId` 마이그레이션 + B 받은 후원 합계 | 시나리오 19, KR4 테스트 |
| 3 | C 채널 페이지 + 닉네임 링크 | 시나리오 20 |
| 4 | D 프로필 편집(소개·이미지·닉네임) | 테스트 계정 403 테스트 |

- E2에서 남는 시간이 1.5일보다 적으면 1단계만 한다.
- 2단계는 마이그레이션과 함께만 출시한다. `Broadcast` 조인만으로 합계를 내면 방송을 지울 때 합계가 줄어든다.
- 11/17 E4 동선 테스트에서 실패하면 기능을 더하지 않고 진입점만 고친다.

### 8.2 첫 버전에서 하지 않는 것

- 비밀번호 변경, 이메일 변경, 회원 탈퇴. 탈퇴는 `Donation.donor`의 `Cascade` 때문에 후원 기록이 지워지는 문제를 먼저 정해야 한다
- 시청 기록, 방송 통계(시청자 수 집계 기반이 없다), 채팅 차단·매니저
- 배너, 소셜 링크, 방송 일정, 채널 공지
- 공개 팔로워 목록, 내역 페이지네이션·기간 필터, CSV 내보내기
- 정산·출금 (PRD-lime 8.2와 같다)

### 8.3 인수 시나리오 (PRD 8.3에 이어 붙인다)

17. B로 로그인 → 헤더 닉네임 → "마이페이지" → "라임 내역"에 충전·후원이 시간순으로 있고, 맨 위 행의 잔액이 현재 잔액과 같다. 비로그인으로 `GET /api/me/lime/ledger` → 401
18. B의 "보낸 후원"에 직접결제·라임 후원이 함께 있다. A가 그 방송을 지우면 그 행이 "삭제된 방송"과 함께 남는다
19. A로 로그인 → 스튜디오 "후원"에 모든 방송의 합계가 있다. 방송 하나를 지워도 합계가 그대로다. "팔로워"에 B가 있다
20. 비로그인으로 A의 방송 카드 닉네임 → `/channels/<A id>`에 소개·팔로워 수·방송 목록이 보이고, A가 LIVE면 맨 위에 그 방송이 있다. A 본인에게는 팔로우 버튼이 없다
21. A로 "프로필"에서 닉네임 변경 → "테스트 계정은 닉네임을 바꿀 수 없습니다." 소개와 프로필 이미지는 바뀌고 채널 페이지에 반영된다
