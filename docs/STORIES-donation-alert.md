### Stories

#### S0 (스파이크): 가려진 송출 탭의 폴링과 소리
**개발자로서, 다른 창을 공유해 송출하는 동안 가려진 송출 탭이 새 후원을 몇 초 안에 찾고 소리를 낼 수 있는지 알고 싶다. 그래야 알림음(S3)을 넣을지 정할 수 있다.**

Acceptance Criteria:
- [ ] PC Chrome에서 다른 창을 공유해 송출하고 송출 탭을 가린 채, 1분 뒤와 6분 뒤 후원의 감지 지연을 기록했다
- [ ] 같은 조건에서 Web Audio 소리가 나는지 기록했다
- [ ] 시스템 소리를 송출할 때 시청 탭에서 알림음이 들리는지 기록했다
- [ ] 결과와 판정(S3 진행/중단)을 DISCOVERY 문서의 E3에 적었다

Priority: P0 | Effort: S | Dependencies: none | **Spike**

---

#### S1: 송출 화면 새 후원 토스트
**스트리머로서, 송출 중에 후원이 오면 송출 화면에서 바로 알고 싶다. 그래야 방송에서 후원자에게 반응할 수 있다.**

Acceptance Criteria:
- [ ] `LIVE` 송출 화면에서 새 `PAID` 후원이 오면 다음 폴링(5초) 안에 "{닉네임}님이 {금액}원 후원"(라임은 "라임")과 메시지가 토스트로 뜬다
- [ ] 화면을 처음 열었을 때와 새로고침했을 때 이미 있던 후원은 띄우지 않는다
- [ ] 토스트는 6초 뒤 사라지고, 화면 읽기 프로그램에는 `aria-live="polite"`로 읽힌다
- [ ] 390px 폭에서 토스트가 "방송 종료" 버튼과 카메라 전환을 가리지 않는다

Priority: P0 | Effort: M | Dependencies: none

---

#### S2: 송출 화면 받은 후원 목록과 합계
**스트리머로서, 토스트를 놓쳐도 이번 방송에 누가 얼마를 후원했는지 송출 화면에서 보고 싶다. 그래야 다른 창을 보다 돌아와도 놓친 후원을 읽어 줄 수 있다.**

Acceptance Criteria:
- [ ] 송출 화면 오른쪽에 시청 화면의 채팅 패널 자리와 같은 사이드 패널을 두고, 그 안에 이번 방송의 후원 합계, 건수, 최근 후원 목록을 둔다. 송출 방법 탭을 바꿔도 남는다(S9가 같은 패널에 채팅을 넣는다)
- [ ] 새 후원은 목록 맨 위에 붙고, 방금 온 후원이 잠시 강조된다
- [ ] 스트리머에게 "후원하기" 버튼이 보이지 않는다
- [ ] 후원이 없으면 "아직 후원이 없습니다."가 보인다

Priority: P0 | Effort: M | Dependencies: S1과 같은 폴링을 쓴다 | **결정(11/15)**: 채팅창 쪽에 둔다

---

#### S3: 송출 화면 알림음
**PC로 송출하는 스트리머로서, 공유한 다른 창을 보고 있어도 후원이 왔다는 것을 소리로 알고 싶다. 그래야 송출 탭을 계속 확인하지 않아도 된다.**

Acceptance Criteria:
- [ ] 새 후원마다 짧은 알림음이 한 번 난다(소리 파일 없이 Web Audio로 만든다)
- [ ] 송출 화면에 알림음 켜기/끄기가 있고 기본은 켬이다. 선택은 이 브라우저에 기억한다(저장이 막혀도 동작한다)
- [ ] 송출 탭이 가려진 상태에서도 S0에서 잰 지연 안에 소리가 난다
- [ ] 송출을 시작하지 않은 화면에서는 소리가 나지 않는다

Priority: P1 | Effort: S | Dependencies: S0 성공, S1

#### S4: 가려진 송출 탭의 제목 표시
**스트리머로서, 송출 탭을 보지 않는 동안 온 후원이 몇 건인지 탭 제목에서 보고 싶다. 그래야 소리를 놓쳐도 돌아갈 때를 안다.**

Acceptance Criteria:
- [ ] 송출 탭이 가려진 동안 새 후원이 오면 탭 제목 앞에 "(N) "이 붙는다
- [ ] 송출 탭을 다시 보면 원래 제목으로 돌아온다
- [ ] 탭이 보이는 동안에는 제목을 바꾸지 않는다

Priority: P2 | Effort: S | Dependencies: S1

---

#### S5: 시청 화면 플레이어 위 후원 배너
**시청자로서, 방송을 보는 중에 누가 후원하면 영상 위에서 바로 보고 싶다. 그래야 채팅과 스트리머의 반응을 함께 이해할 수 있다.**

Acceptance Criteria:
- [ ] `LIVE` 시청 화면에서 새 후원이 오면 다음 폴링(5초) 안에 플레이어 위에 "{닉네임}님이 {금액}원 후원"과 메시지 배너가 6초 동안 뜬다. 비로그인 시청자에게도 뜬다
- [ ] 처음 열었을 때 이미 있던 후원은 띄우지 않는다. `READY`·`ENDED`(다시보기)에서는 띄우지 않는다
- [ ] 배너가 플레이어 조작(재생, 음량, 전체 화면)의 클릭을 막지 않는다
- [ ] 플레이어 전체 화면(컨테이너 전체 화면)에서도 배너가 보인다. iOS 네이티브 전체 화면에서는 보이지 않는 것을 README에 한계로 적는다
- [ ] 후원자 본인에게도 배너가 뜨고, 기존 "후원이 반영되었습니다"는 그대로 둔다

Priority: P0 | Effort: M | Dependencies: none (S1과 감지 로직을 공유)

#### S6: 여러 후원이 몰릴 때 순서대로 보이기
**스트리머와 시청자로서, 후원이 한꺼번에 여러 건 와도 하나도 겹치거나 빠지지 않고 보고 싶다. 그래야 모든 후원자가 같은 대접을 받는다.**

Acceptance Criteria:
- [ ] 한 번의 폴링 응답에 새 후원이 여러 건이면 오래된 것부터 하나씩 띄운다
- [ ] 기다리는 알림이 4건을 넘으면 남은 것을 "외 N건 후원" 한 장으로 묶는다
- [ ] 네트워크가 끊겼다 돌아오면 그 사이 온 후원도 이 규칙대로 띄운다
- [ ] 같은 후원은 두 번 띄우지 않는다

Priority: P1 | Effort: S | Dependencies: S1, S5

#### S7: 금액별 강조
**시청자로서, 큰 후원은 더 눈에 띄게 보고 싶다. 그래야 방송의 중요한 순간을 놓치지 않는다.**

Acceptance Criteria:
- [ ] 10,000 이상과 50,000 이상 후원은 토스트·배너의 색과 표시 시간이 다르다(원·라임 같은 기준)
- [ ] 색만으로 구분하지 않고 문구나 아이콘으로도 구분한다
- [ ] 라이트·다크 모드 모두에서 대비가 충분하다

Priority: P2 | Effort: S | Dependencies: S1, S5

#### S8: 채팅에 후원 줄
**시청자로서, 후원이 채팅 흐름 안에 강조된 줄로 남기를 원한다. 그래야 배너를 놓쳐도, 다시보기에서도 그 시점의 후원을 읽을 수 있다.**

Acceptance Criteria:
- [ ] 후원이 `PAID`가 되는 같은 트랜잭션에서 채팅에 후원 줄이 생긴다(카드 승인, 라임 후원 둘 다)
- [ ] 같은 승인이 다시 와도 후원 줄은 하나다(DB에서 후원당 하나로 막는다)
- [ ] 후원 줄은 일반 채팅과 다르게 보이고 닉네임·금액·메시지를 담는다
- [ ] 다시보기의 "채팅 기록"에서 후원 시점에 후원 줄이 나온다
- [ ] 방송을 지우면 후원 줄은 채팅과 함께 지워지고 후원 행은 남는다(#114)

Priority: P1 | Effort: L | Dependencies: #150(같은 트랜잭션을 건드린다) | **DB 변경**: `pm-skills.md` 표에 따라 이 스토리만 `/pm-execution:red-team-prd` → PRD 반영 후 이슈

#### S9: 송출 화면 채팅

- [ ] 스트리머가 보낸 채팅이 시청 화면에 보인다
- [ ] 390px 폭에서 미리보기와 종료 버튼을 밀어내지 않는다(접거나 아래로 둔다)
- [ ] S8이 들어가면 후원 줄도 여기 보인다

Priority: P1 | Effort: M | Dependencies: none | **Design input**: 모바일 배치

- [ ] 녹화 시작 시각을 모르는 방송(`recordingStartedAt` 비어 있음)에는 표시하지 않는다

#### S12: 방송별 후원 순위
**시청자와 스트리머로서, 이 방송에서 누가 가장 많이 후원했는지 순위로 보고 싶다. 그래야 스트리머는 큰 후원자에게 감사를 전하고, 시청자는 후원이 쌓이는 모습을 볼 수 있다.**

Acceptance Criteria:
- [ ] 시청 화면 후원 영역과 송출 화면 후원 목록(S2)에 이 방송의 후원 순위 상위 N명이 닉네임과 누적 금액으로 보인다
- [ ] 누적 금액은 이 방송의 `PAID` 후원만 셈하고, 카드(원)와 라임을 1:1로 합친다. 금액은 "원"으로 적는다
- [ ] 누적 금액이 같으면 이 방송에 먼저 후원한 사람이 위다
- [ ] 순위는 서버가 전체 후원으로 계산한다. 최근 50건 목록과 상관없이 맞다
- [ ] `LIVE`에서는 5초 폴링마다 갱신되고, `ENDED`(다시보기)에서도 최종 순위가 보인다. 후원이 없으면 순위 영역을 숨긴다
- [ ] N은 5로 시작해 PC·390px 스크린샷을 보고 정한다(11/15 결정: UI 보고 판단). 정한 값과 스크린샷을 PR에 남긴다

Priority: P1 | Effort: M | Dependencies: none (S2가 있으면 송출 화면에도 붙인다) | **API 변경**: `GET /broadcasts/:id/donations` 응답에 `ranking` 필드를 더한다. DB 변경 없음

#### S13: 순위 변동 강조
**시청자로서, 새 후원으로 1위가 바뀌면 그 순간을 알고 싶다. 그래야 방송의 분위기를 함께 느낄 수 있다.**

Acceptance Criteria:
- [ ] 폴링 결과 1위가 바뀌면 순위 영역의 1위 행이 잠시 강조되고, 해당 후원의 배너(S5)에 "1위"가 붙는다
- [ ] 처음 열었을 때의 순위는 변동으로 보지 않는다
- [ ] 강조는 색만이 아니라 문구로도 알 수 있다

Priority: P2 | Effort: S | Dependencies: S5, S12

### Technical Notes

- **감지 로직 하나**: `useNewDonations(broadcastId)` 같은 훅 하나가 기존 `usePolledApi`로 `GET /broadcasts/:id/donations`를 읽는다. 첫 응답은 기준선으로만 쓰고, 이후 응답에서 처음 보는 `id`를 오래된 순으로 큐에 넣는다. S1·S5·S6이 이 훅을 쓴다.
- **폴링을 늘리지 않는다**: 시청 화면은 `DonationPanel`이 이미 5초마다 같은 API를 부른다. 폴링을 `BroadcastPage`로 올려 패널과 배너가 같은 응답을 쓰게 한다. 송출 화면은 새로 5초 폴링 하나를 더한다.
- **순위 집계(S12)**: 목록 API는 최근 50건만 주므로 웹에서 순위를 만들 수 없다. 서버에서 `donation.groupBy({ by: ['donorId'], where: { broadcastId, status: 'PAID' }, _sum: { amount }, _min: { approvedAt } })`를 금액 내림차순, 첫 후원 오름차순으로 5개 읽고 닉네임을 붙인다. raw SQL을 쓰지 않으니 채점기 tagged template 규칙과 무관하다. 기존 `@@index([broadcastId, status, approvedAt])`가 필터를 받친다. 기존 응답에 `ranking`을 더하므로 요청 수는 늘지 않는다.
- **API·DB 변경**: S12(응답 필드 추가)와 S8(DB) 말고는 없다. WebSocket·SSE는 도입하지 않는다(DISCOVERY 문서 참고).
- **전체 화면**: `PlayerControls`는 컨테이너에 `requestFullscreen`을 건다. 배너를 그 컨테이너 안에 두면 전체 화면에서도 보인다. iOS는 `webkitEnterFullscreen`(네이티브)이라 보이지 않는다.
- **알림음**: Web Audio 오실레이터로 만들어 소리 파일과 라이선스가 필요 없다. 송출 시작 버튼 클릭 뒤에만 재생하므로 자동재생 정책에 걸리지 않을 것으로 본다(S0에서 확인).
- **50건 한계**: 목록 API는 최근 50건만 준다. 5초 사이 50건을 넘으면 일부를 놓친다. 무시한다.
