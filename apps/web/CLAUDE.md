# 웹 앱 (apps/web) UI 지침

UI를 만들거나 고치기 전에 이 파일을 읽는다. 여기 없는 결정이 필요하면 기존 화면과 같은 방식을 따르고, 새로 정한 것은 이 파일에 추가한다.

## 서비스 정체성

- 이름: **Lime**. 화면 문구, `<title>`, 로고에 이 이름만 쓴다.
- 로고: `AppLayout`의 `Logo`. "L", 점 없는 "ı", "me" 글자에 i의 점을 라임색 원으로 따로 그린다. 점은 진한 라임 테두리를 두른 라임 원이다. 첫 로드에 한 번, hover·focus 때 다시 통통 튄다(`dot-bounce`). 계속 반복하지 않는다. `prefers-reduced-motion: reduce`면 튀지 않는다. 이미지 파일 없이 CSS로 그린다.
- 탭 제목: 화면마다 `useDocumentTitle`(`src/use-document-title.ts`)을 한 줄로 부른다. `<화면 이름> - Lime`이고, 시청 화면은 `<방송 제목> - Lime`, 송출 화면은 `[송출] <방송 제목> - Lime`이다(송출 탭과 시청 탭을 함께 열어도 구분된다). 방송을 읽기 전에는 `Lime`이다.
- 파비콘: `public/favicon.svg`. 로고의 "Lı"와 라임 점을 흰 둥근 사각형에 그린다. 색은 `tokens.css`와 같은 값을 직접 적는다(SVG 파일은 CSS 변수를 못 읽는다). `index.html`에 `description`과 `og:title`·`og:description`·`og:type`을 둔다. 방송별 OG는 서버 렌더링이 필요해 두지 않는다.
- Twitch·치지직은 **레이아웃과 정보 배치만** 참고한다. 그 서비스의 로고, 색(Twitch 보라, 치지직 초록), 이름, 아이콘, 문구를 쓰지 않는다.

## 색·글꼴·간격

- 값은 `src/styles/tokens.css`의 CSS 변수로만 쓴다. 컴포넌트 CSS에 색 코드나 px 간격을 직접 적지 않는다. 새 값이 필요하면 토큰을 먼저 추가한다.
- 테마는 밝은 배경 하나다(Twitch 밝은 테마처럼 흰 톤, `--color-bg` #f7f7f8, 상단 바·카드 `--color-surface` #ffffff). 어두운 테마는 만들지 않는다. 영상이 나오는 자리만 `--color-video-bg`(검정)를 쓴다.
- 브랜드 색은 라임 `--color-brand`(#c4f04d). 치지직의 민트빛 초록과 다른 노란빛 연두다. 흰 배경에서 대비가 1.3:1이라 **면(버튼 배경, 로고 점)에만** 쓰고 글자는 `--color-on-brand`로 얹는다. 링크 글자·포커스 테두리·hover 외곽선처럼 흰 바탕 위 글자·선은 진한 라임 `--color-brand-strong`(#4a7a0c, 흰 배경 대비 5.1:1)을 쓴다. 주요 버튼(방송 시작, 로그인)과 링크 강조에만 쓴다.
- 상태 색: LIVE `--color-live`(빨강), 방송 준비 중 `--color-ready`(파랑), 방송 종료 `--color-ended`(회색).
- 글꼴: Pretendard Variable(`pretendard` 패키지, OFL-1.1). `--font-sans`로 쓴다.
- 간격은 4px 단위 `--space-1`(4px)~`--space-8`(32px), 모서리는 `--radius-sm/md/lg`.

## 상태 배지

방송 상태는 `src/components/StatusBadge.tsx`로만 표시한다. 문구는 GLOSSARY를 따른다.

| 상태 | 문구 |
|---|---|
| `READY` | 방송 준비 중 |
| `LIVE` | LIVE |
| `ENDED` | 방송 종료 |

"방송 중", "ON AIR", "종료됨", "대기" 같은 다른 문구를 쓰지 않는다.

## 레이아웃 골격

모든 화면은 `src/layout/AppLayout.tsx` 안에 그린다. 상단 바(높이 `--header-height` 56px: 로고, 메뉴, 오른쪽 끝에 로그인/사용자 메뉴) 아래에 본문이 오고, 본문 최대 폭은 `--content-max-width`(1440px)다.

본문 왼쪽에는 모든 화면에 팔로우 패널(`layout/FollowPanel`)을 둔다. 폭 1280px 이상은 펼친다(`--follow-panel-width` 240px). 1024~1279px는 이니셜 원과 LIVE 점만 보이게 접는다(`--follow-panel-collapsed-width` 56px). 접히면 제목·안내 문구는 숨기고 항목의 `title`로 닉네임·방송 제목을 보인다. 1024px 미만은 패널을 숨기고 상단 메뉴에 "팔로잉"(`/following`, 로그인했을 때만)을 둔다. 폭에 따라 자동으로만 바뀌고 접기·펼치기 버튼은 없다.

- 로그인: 제목 "팔로우한 스트리머". LIVE는 이니셜 원과 빨간 점(`--color-live`), 닉네임, 방송 제목(한 줄 말줄임), 시청 화면 링크. 오프라인은 회색 원과 "오프라인"이고 링크가 없다(스트리머 페이지가 없다). 팔로우가 없으면 "방송을 보다가 팔로우하면 여기에 보입니다."
- 비로그인: 제목 "LIVE 중인 방송", `GET /api/broadcasts?status=LIVE`의 앞 5개, "로그인하고 스트리머를 팔로우해 보세요" 링크(로그인 뒤 이 화면으로 돌아온다). 30초마다 다시 읽는다.
- 아이콘·이미지는 쓰지 않는다. 아바타는 닉네임 첫 글자다.

| 화면 | 경로 | 배치 (참고: Twitch·치지직) |
|---|---|---|
| 방송 목록 | `/` | 맨 위에 소개 한 줄("설치 없이 브라우저로 화면이나 카메라를 방송하고, 누구나 로그인 없이 시청합니다.", 작은 회색 글자). 로그인 상태와 관계없이 남겨 로그인해도 높이가 바뀌지 않는다. 로그인 상태가 `anonymous`일 때만 그 옆(좁으면 아래)에 테스트 계정 버튼(`TestAccountLogin`의 `inline`, 한 줄)을 두고, 누르면 `logInAsTestAccount`로 로그인한 뒤 홈에 머문다. 서버가 계정을 주지 않으면 버튼 영역이 없다. 실패하면 "로그인하지 못했습니다. 잠시 후 다시 시도해 주세요." 그 아래 카드 그리드 `repeat(auto-fill, minmax(280px, 1fr))`. 카드 = 16:9 썸네일 영역(왼쪽 위에 상태 배지) + 제목 + 스트리머 이름. LIVE 먼저, 그다음 방송 준비 중(만든 지 24시간 안의 `READY`), 그다음 방송 종료. 위에 필터 탭 전체·LIVE·방송 준비 중·방송 종료·다시보기(`/?status=LIVE`·`READY`·`ENDED`·`REPLAY`). 방송 준비 중 탭이 비면 "준비 중인 방송이 없습니다." 다시보기는 `GET /api/replays`(녹화가 있는 방송 종료, 늦게 끝난 순). 탭 위에 검색창(`type="search"`, 화면에 보이지 않는 label "방송 검색", 폭은 최대 `--list-search-max-width`, 좁은 화면은 한 줄 전체)을 둔다. 현재 탭에서 받아 온 목록을 브라우저에서 제목·스트리머 닉네임으로 거른다(부분 일치, 대소문자·앞뒤 공백 무시). API는 부르지 않는다. 검색어는 `?q=`에 `replace`로 남기고, 탭 링크도 `q`를 붙여 탭을 바꿔도 남는다. 맞는 방송이 없으면 "'<검색어>'와 맞는 방송이 없습니다."와 "검색어 지우기" 버튼(누르면 검색창에 포커스)을 띄우고, 목록 자체가 비면 탭의 빈 문구를 그대로 쓴다. 목록은 30초마다 다시 읽는다. 썸네일은 `components/BroadcastThumbnail`(그림 고르기는 `ThumbnailPicture`)이 그린다. 상태별로 쓸 그림의 순서를 표(`IMAGE_ORDER`)로 둔다. `READY`는 `standbyImageUrl`(스트리머의 기본 대기 이미지) → 첫 글자, `LIVE`·`ENDED`는 `thumbnailUrl`(송출 화면 캡처) → `standbyImageUrl` → 첫 글자다. 캡처 썸네일(`/thumbnails/<방송 id>/live.jpg?v=…`)은 16:9 칸을 채우고(`object-fit: cover`), 대기 이미지(`/thumbnails/users/<사용자 id>/standby.<확장자>?v=…`)는 스트리머가 올린 그림 전체가 보이게 `--color-video-bg` 위에 `object-fit: contain`으로 그린다. 둘 다 `loading="lazy"`, 제목이 바로 아래에 있어 `alt=""`다. 그림이 로드에 실패하면 다음 그림으로 넘어가고(URL이 바뀌면 다시 시도한다), 남은 그림이 없으면 제목 첫 글자를 상태색 글자(`--font-size-display`)로 크게 그리고, 배경은 옅은 상태색 면(`--color-live-soft`·`--color-ready-soft`·`--color-ended-soft`)으로 칠한다. LIVE 카드는 오른쪽 아래에 경과 시간을 분 단위(`N분`·`H시간 M분`, 1분 미만은 "방금 시작")로 작게 보이고 1분마다 갱신한다 |
| 시청 | `/broadcasts/:id` | 넓은 화면: 왼쪽 16:9 플레이어, 아래에 제목·스트리머·상태 배지·설명. LIVE면 플레이어(`components/LivePlayer`: LL-HLS, MediaSource가 있으면 hls.js 저지연 모드, 없으면(iPhone) 네이티브 HLS, 준비 전에는 "방송을 불러오는 중입니다"를 띄우고 다시 시도). 브라우저 기본 컨트롤(`controls`)은 쓰지 않고 `components/player/PlayerControls`(재생 엔진을 모르는 표시 전용, 상태는 `useMediaState`가 video 이벤트로 읽는다)를 영상 위에 올린다. 아래 그라데이션 바에 재생/일시정지, 음소거(PC는 hover·focus 때 볼륨 슬라이더를 펼치고, 터치 기기는 숨긴다), LIVE 표시, 오른쪽 끝에 전체화면. LIVE 표시는 라이브 끝(hls.js `liveSyncPosition`, 네이티브는 `seekable` 끝)에서 3초 이내면 빨간 점 "LIVE", 더 뒤처지면 회색 점 "라이브로 이동" 버튼이고 누르면 라이브 끝으로 이동해 재생한다. 일시정지 중이면 가운데에 큰 재생 버튼. 영상 클릭은 재생/일시정지, 더블클릭은 전체화면(미지원이면 iPhone `webkitEnterFullscreen`), 터치에서 숨은 컨트롤을 첫 탭하면 컨트롤만 띄운다. 3초 입력이 없으면 컨트롤과 커서를 숨기고, 일시정지 중·컨트롤에 포커스가 있을 때·슬라이더를 끄는 중에는 숨기지 않는다. 키보드는 플레이어에 포커스가 있을 때만 받는다(Space·K 재생, M 음소거, F 전체화면, ↑↓ 볼륨 10%. 한글 자판에서도 되도록 `event.code`로 읽는다). 볼륨만 `localStorage`(`lime.player.volume`)에 기억하고 음소거 여부는 기억하지 않는다. 볼륨 0은 기억하지 않는다(다음 방문이 무음으로 시작하지 않게). 음소거와 볼륨 0은 같은 "음소거" 상태로 보인다: 아이콘은 음소거, 버튼 이름은 "음소거 해제", 슬라이더는 0(실제 볼륨은 남겨 해제하면 돌아간다). 해제할 때 볼륨이 0이면 1로 올린다. 음소거 중 슬라이더를 올리거나 ↑ 키를 누르면 음소거가 풀린다(#106). 아이콘은 `player/PlayerIcons`의 직접 그린 인라인 SVG(`currentColor`)다. 소유자가 보면 플레이어를 음소거로 시작하고 아래에 하울링 안내를 띄운다(T7). 다른 시청자는 소리를 켠 채 시작하고, 브라우저가 자동 재생을 막으면 음소거로 재생한다. 음소거로 시작했으면 왼쪽 위에 "소리 켜기" 버튼을 띄우고, 누르거나 직접 음소거를 바꾸면 사라진다. 상태는 5초마다, 재생 오류 때는 바로 다시 조회해 `ENDED`면 플레이어를 내리고 "방송이 끝났습니다."를 띄운다(PRD §7.4 T9). `ENDED`이면서 `recordingFiles`가 있으면 그 자리에 다시보기 플레이어(`components/ReplayPlayer`: `/recordings/<파일>`을 재생)를 둔다. 라이브와 같은 `PlayerControls`를 `live` 없이 올린다. 길이를 아는 녹화라 LIVE 표시 대신 바 위 한 줄에 탐색 바("재생 위치", 라임 `accent-color`)를, 볼륨 옆에 `현재 / 전체` 시간(`formatClock`)을 두고, 키보드 ←→로 5초씩 이동한다. 전체화면 왼쪽에 재생 속도 버튼을 두고, 누를 때마다 `1x → 1.25x → 1.5x → 2x → 0.5x → 1x` 순서로 바꾼다. 버튼 글자는 현재 속도, 이름은 "재생 속도 1.5배"다. `playbackRate`와 `defaultPlaybackRate`를 함께 바꿔 다음 부로 넘어가도 속도가 남는다(`src`를 바꾸면 브라우저가 `playbackRate`를 기본값으로 되돌린다). 속도는 기억하지 않아 새로 열면 1배속이고, 라이브 플레이어에는 속도 버튼이 없다. 송출 연결이 끊겼다 이어지면 녹화가 여러 파일로 나뉘므로, 한 부가 끝나면 다음 부를 이어서 재생하고(부를 바꿔도 같은 video 요소에 `src`만 바꿔 볼륨·음소거·컨트롤이 그대로 남는다), 둘 이상이면 플레이어 아래에 "1부"·"2부" 버튼(`aria-pressed`)과 나뉜 이유 한 줄을 둔다. 녹화 파일은 API 녹화 정리 작업(30초 주기)이 종료 뒤에 채우므로, `ENDED`인데 `recordingFiles`가 비어 있고 `endedAt`부터 90초(`REPLAY_WAIT_MS`, 응답을 받은 시각 기준)가 지나지 않았으면 5초 조회를 계속하고 "방송이 끝났습니다." 아래에 "다시보기를 준비하는 중입니다."(`role="status"`)를 띄운다. 파일이 생기면 새로고침 없이 다시보기 플레이어로 바꾸고 조회를 멈춘다. 90초가 지난 뒤 첫 응답에도 비어 있으면 녹화가 없는 방송으로 보고 그 줄을 지우고 조회를 멈춘다. 이미 90초가 지난 방송을 열면 한 번만 읽는다. 스트리머 이름 옆에 팔로우 버튼(`follows/FollowButton`): "팔로우"(라임 면)/"팔로잉"(테두리), `aria-pressed`. 누르면 바로 바뀌고 목록을 다시 읽은 뒤 그 값을 따른다. 실패하면 원래 상태로 되돌리고 짧은 오류 문구를 띄운다. 소유자에게는 없고, 비로그인은 버튼 대신 "로그인하고 팔로우" 링크(로그인 뒤 이 화면으로 돌아온다). 설명 아래에 소유자에게만 송출 화면 링크(방송 종료 제외)와 방송 종료(LIVE일 때만)·수정·삭제 버튼(`OwnerActions`, 종료와 삭제는 한 번 더 확인, LIVE 삭제는 확인 문구에 방송도 종료된다고 적는다). 폭 1024px 이상은 오른쪽 열(`--side-panel-width`)에 `components/BroadcastSidePanel`을 두고, 패널은 메시지 수와 관계없이 화면 높이(`100vh − 헤더 − 여백`)를 꽉 채운 채 붙어 있고, 제목·탭과 입력창은 제자리에 두고 목록만 스크롤한다(Twitch·치지직 방식). 좁은 화면(1024px 미만, Twitch 모바일 웹 방식): 페이지가 헤더 아래 화면(`100dvh − Esc·바깥 탭·"닫기"로 닫고 포커스는 `···`로 돌아온다. 부를 고르면 재생하고 시트를 닫는다. 넓은 화면에서 플레이어 주변에 두던 것을 좁은 화면에서 시트로 옮길 뿐 각각 한 번만 그린다. 어디에 둘지는 `useWideScreen`(`matchMedia('(min-width: 1024px)')`)으로 `BroadcastPage` 한 곳에서 정한다. 재생 중인 부는 페이지가 갖고(`ReplayPlayer`의 `part`·`onPart`), 부 버튼은 `ReplayParts`로 따로 그린다. 패널은 상태 표(`SIDE_PANEL`)로 고른다. `READY`·`LIVE`는 제목 "채팅"의 채팅 패널(`components/ChatPanel`): 한 줄에 닉네임과 글을 붙여 쓰고 뒤에 시각(시:분, 마우스를 올리면 날짜까지)을 작게 둔다. 오래된 순이고 처음과 내가 보낸 뒤에는 맨 아래(최신)로 스크롤하며, 위로 올려 읽는 중이면 새 채팅이 와도 위치를 지킨다. `use-chat-feed`가 1초마다 `GET /api/broadcasts/:id/chat?after=<마지막으로 받은 id>`로 새 메시지만 읽고, 200개가 꽉 차면 바로 다음 페이지를 읽는다(실시간 푸시 없음, PRD §8.2). 목록은 `chat.ts`의 리듀서가 `(createdAt, id)` 순으로 정렬하고 id로 중복을 거른다. 내가 보낸 채팅은 응답을 받자마자 넣는다. 입력창 "채팅 쓰기"(200자, `n/200`, `enterKeyHint="send"`), "보내기". Enter로 보내고 Shift+Enter는 줄을 바꾼다. 한글 조합을 끝내는 Enter(`isComposing`, Safari는 `keyCode` 229)는 보내지 않는다. 빈 글과 보내는 중에는 Enter도 버튼도 보내지 않는다. 좁은 화면은 "보내기" 버튼을 CSS로 숨긴다. 댓글 입력은 Enter로 보내지 않는다. 409는 API 문구(`serverMessage`)를 띄우고 401은 로그인 화면으로 보낸다. 비로그인은 입력창 대신 "로그인하고 채팅에 참여해 보세요" 링크(로그인 뒤 이 화면으로 돌아온다). 채팅은 작성자도 고치거나 지울 수 없어 버튼이 없다(운영자·스트리머 삭제는 아직 없다). `ENDED`는 탭 "댓글"(기본)·"채팅 기록"이다(`role="tablist"`, 선택된 탭만 `tabIndex=0`, ←/→·Home·End로 옮기면 포커스와 선택이 함께 옮는다, `role="tabpanel"`은 `aria-labelledby`로 탭을 가리킨다). "채팅 기록"은 처음 열 때 채팅을 끝까지 한 번 읽고 읽기 전용으로 보인다(입력창·삭제 없음). 다시보기를 재생하거나 탐색하면 그 장면까지 오간 채팅만 보인다(`replay-chat.ts`). 채팅은 `createdAt` − 파트 시작(`recordingParts[].startedAt`) − 3초(시청 지연) 자리에 놓고, `READY` 때 채팅은 1부 0초, 송출이 끊긴 사이의 채팅은 다음 부 0초에 보인다. 탐색하면 바로 다시 거르고, 맨 아래(최신)를 지키는 스크롤은 실시간 채팅과 같다. 재생·탐색 전이거나 시작 시각이 없는 녹화면 전체를 시간순으로 보이고, 거른 결과가 비면 "이 장면까지 오간 채팅이 없습니다." 탭을 오가도 댓글 입력과 기록은 남는다. 상태는 화면이 5초마다 읽으므로 LIVE에서 방송 종료로 바뀌면 새로고침 없이 탭으로 바뀐다. | 송출 | `/studio/broadcasts/:id` | 소유자만. 위에 제목과 "시청 화면 열기" 링크. 폭 960px 이상은 두 열(왼쪽 `minmax(0, 2fr)` 16:9 미리보기(소리 끔), 오른쪽 `minmax(320px, 1fr)`에 상태 한 줄·소스별 패널·버튼), 좁으면 한 열. 캡처 소스는 `pages/captureSources`의 `CaptureSlot`과 소스별 레지스트리(`CAPTURE_SOURCES`: 버튼 문구, 시작 함수, 실패 문구)로 다룬다. 화면 공유를 지원하는 PC 브라우저는 "화면 공유"(주 버튼)와 "카메라 켜기", 그 밖은 "카메라 켜기"만. 화면 공유 패널: 송출 사전 점검(`components/PcPreflight`, 미터·경고, Chrome·Edge 외 브라우저 경고), 마이크 끄기·켜기(`aria-pressed`), 다시 선택(화면 소리가 없으면 강조). 카메라 패널: 전면·후면 카메라와 화면 꺼짐 방지 상태 한 줄. 전면 카메라 미리보기는 좌우 반전한다(시청자에게는 반전하지 않은 영상이 간다). 카메라가 둘 이상이면 "후면 카메라로 전환"/"전면 카메라로 전환"을 버튼 묶음 맨 위에 둔다. 송출 연결을 만드는 중에는 전환을, 전환 중에는 방송 시작을 막는다. 카메라 권한을 거부하면 `components/PermissionGuide`(iPhone·Android별 허용 방법)를 띄운다. 버튼 흐름: 소스 켜기 → 방송 시작(PC 화면이면 이 클릭 안에서 AudioContext resume, T7) → 방송 종료(한 번 더 확인). 송출 연결은 `publish/usePublishSession`(`MediaStream`을 받아 토큰·WHIP·종료 API를 맡고, `replaceTrack`으로 송출 중 화면·카메라를 바꾼다. 카메라 전환은 `releaseTrack('video')`로 송출 복제본을 먼저 놓은 뒤 새 카메라를 연다. 휴대폰은 카메라를 하나만 열 수 있다)이, 캡처는 화면이 맡는다. 공유 중지·장치 꺼짐은 송출 중이면 종료 API를 부르고 사유를 종료 화면에 적으며, 연결 전이면 송출만 멈춘다. 송출 중에 마이크가 빠지면 "처음부터 다시" 없이 화면 소리만 나간다고 알린다. 페이지를 떠난 뒤 늦게 얻은 캡처는 멈춘다. 종료하면 캡처를 멈추고 "방송을 종료했습니다."와 시청 화면·내 방송 링크를 띄운다. 이 화면이 송출하지 않는데 방송이 LIVE면(새로고침, 송출 끊김) 방송 종료 버튼을 남긴다. 이미 종료된 방송을 열면 새 방송을 만들라고 안내한다. 송출은 `publish/whipPublisher`(OvenLiveKit WHIP, H.264 고정)로 한다. ICE `failed`(OvenLiveKit `iceStateChange`로 받는다)나 `startStreaming` 뒤 15초(`CONNECT_TIMEOUT_MS`) 안에 `connected`가 오지 않으면 연결을 닫고 실패로 알린다. 화면은 "송출 서버에 연결하지 못했습니다. 네트워크를 바꾸거나 다시 시도하세요."를 띄우고, OME가 송출을 거절했거나 연결하지 못했을 때는 "방송 시작" 자리에 "다시 시도"를 둔다(누르면 새 토큰으로 다시 송출한다). 송출 연결 중·송출 중(`connecting`·`live`)에는 화면을 떠나기 전에 묻는다. 탭 닫기·새로고침은 `beforeunload`로 브라우저 기본 확인창을 띄우고, 앱 안 이동(헤더 링크, 뒤로 가기)은 `useBlocker`로 잡아 "송출 중입니다. 이 화면을 떠나면 방송이 끊깁니다." 확인창(`role="alertdialog"`, "떠나기"·"머무르기", 포커스는 "머무르기", Esc는 머무르기)을 띄운다. "떠나기"면 지금처럼 송출만 끊고 이동한다. 송출 전과 종료 화면에서는 묻지 않는다. 송출이 live인 동안 `publish/thumbnailCapture`가 연결 직후 한 장, 이후 30초마다 미리보기 `<video>`를 가로 480px canvas에 변환 없이 그려(전면 카메라 반전은 CSS뿐이라 시청자가 보는 방향이다) JPEG(0.7)으로 `PUT /api/broadcasts/:id/thumbnail`에 올린다. 실패는 화면에 알리지 않고 다음 주기에 다시 하며, 송출 상태·버튼에 영향을 주지 않는다. 캡처 코드는 이 파일에만 둔다. 폭 960px 미만에서는 카메라 미리보기를 3:4(최대 높이 50vh)로 보이고, 주 버튼 묶음을 세로로 쌓아 화면 아래에 붙인다(엄지 위치). 오른쪽 열 맨 위에 탭 "브라우저로 송출"(기본)·"OBS로 송출"을 둔다(#89, `BroadcastSidePanel`과 같은 WAI-ARIA 탭: 선택된 탭만 `tabIndex=0`, ←/→·Home·End). 왼쪽 미리보기는 탭과 관계없이 그대로다. 두 패널은 늘 그려 두고 `hidden`으로만 숨겨, 탭을 오가도 발급한 주소와 캡처가 남는다. 브라우저 패널은 위의 상태 한 줄·소스별 패널·버튼 그대로다. OBS 패널(`pages/ObsPanel`): 상태 배지와 한 줄(`READY` "OBS에서 방송 시작을 누르면 LIVE가 됩니다.", `LIVE` "송출이 연결되어 있습니다."(브라우저 패널의 "송출 중입니다."와 겹치지 않게, 누가 송출하는지 모르므로 연결만 말한다), `LIVE`이면서 `disconnectedAt`이 있으면 "송출이 끊겼습니다. 30초 안에 다시 연결되지 않으면 방송이 종료됩니다."), "송출 주소" 아래 "URL 발급"(`POST /api/broadcasts/:id/publish-token`에 `{ client: 'obs' }`, 토큰 12시간). 받은 `publishUrl`(같은 출처 경로)은 `location.origin`을 붙인 절대 주소로 읽기 전용 입력창(포커스하면 전체 선택, 360px에서 줄어든다)에 보이고, 옆에 "복사"(`navigator.clipboard.writeText`, "복사했습니다."/"복사하지 못했습니다. 주소를 직접 선택해 복사하세요."), 아래에 만료 시각을 절대 시각("11월 13일 오전 2:30까지 …")으로 적는다. 카운트다운은 두지 않고, 만료 시각에 맞춘 `setTimeout` 하나로 주소를 내리고 "주소가 만료되었습니다. 다시 발급하세요."를 띄운다(서버가 만료 주소를 거절한다). 발급한 뒤 버튼은 "다시 발급"이다. 그 아래 OBS 설정 3줄(서비스 WHIP, 서버 칸에 주소·Bearer 토큰 칸은 비움, 키프레임 간격 1~2초), LIVE면 같은 방송 종료 버튼. 토큰 요청과 오류 문구(403·404·409 `serverMessage`, 401은 로그인 화면)는 `publish/publishTicket`의 `requestPublishTicket(broadcastId, client)` 한 곳에 두고 브라우저 송출(`client: 'browser'`, 5분)도 같이 쓴다. 송출 화면은 방송을 5초마다(`usePolledApi`), 브라우저 송출 상태가 바뀔 때마다 바로 다시 읽는다. 읽은 방송이 `LIVE`이고 `disconnectedAt`이 null인데 이 화면이 송출하고 있지 않으면(OBS나 다른 탭이 송출 중) 브라우저 "방송 시작"·"다시 시도"를 막고 "OBS나 다른 탭에서 송출 중입니다. 브라우저로 송출하려면 그 송출을 먼저 멈추세요."를 띄운다. 한 방송에는 송출 연결이 하나만 된다. `disconnectedAt`이 있으면(송출이 끊기고 30초 재접속 유예 중) 막지 않는다. 그 유예를 브라우저가 이어받을 수 있어야 해서다. 읽은 방송이 `LIVE`면 방송 종료 버튼을 띄우고, 이 화면이 송출하지 않는 동안 `ENDED`를 읽으면(OBS가 유예를 넘겨 끊김, 다른 탭에서 종료) 캡처를 멈추고 "방송이 종료되었습니다." 종료 화면을 띄운다. 이탈 확인(#76)은 이 화면의 브라우저 송출에만 걸고, OBS 송출 중에는 묻지 않는다(페이지를 닫아도 OBS 송출은 끊기지 않는다). OBS 송출에는 썸네일 캡처가 없다 |

## 스타일링: CSS Modules

- 컴포넌트마다 `Foo.module.css`를 옆에 둔다. 전역 CSS는 `src/styles/global.css`(리셋, body, 글꼴)와 `tokens.css`만 쓴다.
- Tailwind나 CSS-in-JS 라이브러리를 들이지 않는다.
- 이유: Vite가 추가 설정 없이 지원하고, 의존성이 늘지 않으며, 색·간격을 토큰 한 곳에서 바꿀 수 있다. Tailwind는 설정 파일과 빌드 플러그인이 늘고, 토큰을 Tailwind 설정과 CSS 변수 두 곳에서 관리하게 된다.

## 라우팅: React Router (선언형 `<Routes>` + data router 한 겹)

- `react-router`의 `<Routes>`/`<Route>`를 `src/AppRoutes.tsx` 한 곳에 모은다. 새 화면은 `src/pages/<Name>Page.tsx`에 만들고 `AppRoutes`의 `AppLayout` 아래에 등록한다.
- `main.tsx`는 `createBrowserRouter([{ path: '*', element: <AuthProvider><AppRoutes /></AuthProvider> }])`를 `RouterProvider`(`react-router/dom`)로 그린다. 경로 매칭은 그 안의 `<Routes>`가 그대로 한다. data router를 쓰는 이유는 `useBlocker`(송출 중 이탈 확인)가 data router 안에서만 동작해서다(#76). loader·action은 쓰지 않는다.
- `RouterProvider`는 `useTransitions={false}`로 쓴다. 기본값(transition)이면 URL 값으로 그리는 입력창(목록 검색 `?q=`)이 키 입력을 따라가지 못해 글자와 한글 조합이 빠진다.
- 테스트는 보통 `MemoryRouter`로 감싼다. 송출 화면(`PublishPage`)을 그리는 테스트는 `src/testing/renderInDataRouter`(`createMemoryRouter` + `RouterProvider`)를 쓴다. `MemoryRouter` 안에서 `useBlocker`를 부르면 오류가 난다.

## API 호출

- `src/api.ts`의 `apiFetch<T>(path, init)`만 쓴다. `path`는 `/api` 뒤의 경로다(`apiFetch('/broadcasts')` → `GET /api/broadcasts`).
- 로그인은 쿠키 세션이라 `apiFetch`가 항상 `credentials: 'include'`를 붙인다. 토큰을 localStorage에 두지 않는다.
- 2xx가 아니면 `ApiError`(`status` 포함)를 던진다. 401이면 로그인 화면으로, 403이면 "권한이 없습니다" 안내로 처리한다.
- 401 규칙: `apiFetch`가 401을 받으면 `onUnauthorized` 구독자(`AuthProvider` 한 곳)에 알리고, 로그인 상태가 `anonymous`로 바뀐다. 로그인·회원가입·테스트 로그인(`/auth/login`·`/auth/signup`·`/auth/test-login`)의 401은 잘못된 입력이라 알리지 않는다. 화면은 지금처럼 `navigate('/login', { state: { from } })`만 하고 로그인 상태를 직접 바꾸지 않는다.
- 화면을 열 때 데이터를 읽는 GET은 `src/use-api.ts`의 `useApi<T>(path)`를 쓴다. `loading`, `loaded`(`data`), `failed`(`error`) 중 하나를 돌려준다.
- 로그인이 필요한 화면은 `AppRoutes`에서 `<Route element={<RequireAuth />}>` 아래에 둔다. 비로그인 방문자는 로그인 화면으로 가고, 로그인하면 원래 경로로 돌아온다.
- 팔로우 목록 `GET /api/me/follows`는 `follows/FollowsProvider`(`AppLayout` 아래 한 곳)만 읽는다. 로그인했을 때 30초마다, 팔로우·언팔로우 직후 바로 다시 읽는다. 패널·팔로우 버튼·`/following`은 `useFollows()`로 같은 목록을 보고, 팔로우·언팔로우도 그 `setFollowing`으로 한다. 화면마다 따로 부르지 않는다.
- 로그인 상태는 `src/auth/auth-context.ts`의 `useAuth()`로 읽는다. `state.status`는 넷 중 하나다. `loading`: `GET /api/auth/me` 응답 전. `anonymous`: 세션이 없다고 API가 답했다(`me`나 다른 요청의 401). `error`: `me`가 401이 아닌 이유(네트워크, 5xx)로 실패해 로그인 여부를 모른다. `authenticated`: `state.user`가 있다. `error`는 비로그인으로 다루지 않는다. 로그인 화면으로 보내지 않고(`RequireAuth`는 아무것도 그리지 않는다), 로그인을 권하는 버튼·링크(테스트 계정 버튼 포함)도 `anonymous`일 때만 보인다. 헤더가 "로그인 상태를 확인하지 못했습니다."와 "다시 시도"(`recheck()`)를 보인다. 화면마다 `me`를 다시 부르지 않는다.
- 개발 중에는 Vite dev proxy가 `/api`를 `http://localhost:${API_PORT}`(기본 3000)로 넘긴다. 그래서 웹과 API가 같은 출처로 보여 쿠키가 그대로 붙는다.
- OME(WHIP 송출, LL-HLS 재생)는 `/app` 아래 같은 출처 경로로 쓴다. 개발 중에는 Vite dev proxy가 `/app`을 `http://localhost:${OME_HTTP_PORT}`(기본 3333)로 넘기고, 운영에서는 Caddy가 같은 일을 한다.
- 녹화 파일은 `/recordings/<방송 id>/<파일>.mp4` 같은 출처 경로로 쓴다. 개발 중에는 Vite dev proxy가 `/recordings`를 `http://localhost:${RECORDINGS_HTTP_PORT}`(기본 8090, compose의 녹화 정적 서버)로 넘기고, 운영에서는 Caddy가 녹화 폴더를 내준다.
- 썸네일은 `/thumbnails/<방송 id>/live.jpg?v=<업로드 시각>`, 기본 대기 이미지는 `/thumbnails/users/<사용자 id>/standby.<확장자>?v=<업로드 시각>` 같은 출처 경로로 쓴다. 개발 중에는 Vite dev proxy가 `/thumbnails`를 `http://localhost:${THUMBNAILS_HTTP_PORT}`(기본 8091, compose의 썸네일 정적 서버)로 넘기고, 운영에서는 Caddy가 썸네일 폴더를 내준다.
- 본문이 `FormData`면 `apiFetch`가 `Content-Type`을 붙이지 않는다(multipart 경계값은 브라우저가 정한다).
- `ApiError.serverMessage`는 API가 보낸 `message`다. 409처럼 API가 사용자용 문구를 주는 경우에만 화면에 그대로 쓴다.

## 문구

- 화면 문구는 한국어, 존댓말 평서문으로 쓴다("방송이 끝났습니다").
- GLOSSARY 용어를 쓴다: 방송, 스트리머, 시청자, 송출. "스트림", "방송자", "호스트"를 쓰지 않는다. "채널"은 스트리머의 설정 묶음을 가리키는 "내 채널" 탭에만 쓰고 방송을 가리키는 말로 쓰지 않는다. "대기"는 "기본 대기 이미지"에만 쓰고 `READY` 상태를 부르는 말로 쓰지 않는다.
